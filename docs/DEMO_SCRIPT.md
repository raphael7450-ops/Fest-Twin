## 평가위원 예상 Q&A 세트

### Q1: 공공 OpenAPI 서버 장애 발생 시 서비스가 중단되지 않는가?

> A: 중단되지 않습니다. Fest-Twin은 Graceful Fallback 아키텍처를 적용했습니다.
>
> - 한국관광공사 TourAPI, KTDB, 관광데이터랩 등 외부 API 응답 실패(HTTP 502) 또는 네트워크 타임아웃 시, 사전 정규화된 샘플 데이터셋으로 자동 전환됩니다.
> - 이때 화면의 "데이터 신뢰도" 배지가 `샘플 데이터 대체 사용`으로 변경되어, 사용자에게 현재 데이터 출처의 변경을 투명하게 고지합니다.
> - 샘플 데이터는 실제 API 응답 스키마와 동일한 형식으로 정규화되어 있으므로, 진단 로직의 일관성이 유지됩니다.
> - 외부 API 복구 시 자동으로 실데이터 조회로 복귀합니다.
>
> 추가 보호 장치: 인메모리 캐시(TTL 10분)가 적용되어, 장애 직전까지 정상 수신된 데이터는 캐시에서 즉시 제공됩니다(평균 응답 0.36ms).

---

### Q2: 수치 추정 결과의 행정적 근거와 신뢰성은 어떻게 보장하는가?

> A: Metric Evidence Drawer(지표 산출 근거 엔진)으로 보장합니다.
>
> 모든 핵심 지표(흥행 예측 지수, 최고 밀집 위험도, 예산 효율성 점수 등) 옆에 [근거 보기] 버튼이 있으며, 클릭 시 다음을 확인할 수 있습니다:
>
> | 항목 | 내용 |
> |------|------|
> | 사용 데이터 | 실제 계산에 사용된 공공 데이터 출처, 조회 시각, 레코드 수 |
> | 산출 방식 | 1~4단계 수식(Formula)과 가중치 계수(Coefficient Badge) |
> | 사용 데이터 상세 | 계산 입력에 사용된 개별 레코드, 매력도 점수, 필드 값 |
> | 해석 시 주의사항 | 데이터 한계, 보정 계수, 오차 범위 안내 |
>
> 또한 보안 비식별 정화가 적용되어, 인증키(serviceKey), 쿠키, 인가 토큰 등 민감 정보는 `[비공개]`로 자동 마스킹됩니다.
>
> 이 체계를 통해 감사원, 상급 기관 질의 시 "이 숫자가 왜 나왔는가?"에 대해 원클릭으로 즉시 답변할 수 있습니다.

### Q3: 타 부서나 상급 기관 제출 시 협업 방식은?

> A: SQLite 서버 영속 저장 + share_token 공유 링크로 지원합니다.
>
> 1. 사용자가 진단 시뮬레이션을 완료하고 [시나리오 저장] 버튼을 누르면, 시나리오 파라미터와 결과 요약이 서버 SQLite에 영속 저장됩니다.
> 2. 저장 시 8자리 공유 토큰(share_token)이 자동 발급됩니다.
> 3. [공유 링크] 버튼을 클릭하면 `https://서버주소/?share_token=xxxxxxxx` 형식의 URL이 클립보드에 복사됩니다.
> 4. 이 URL을 예산과, 안전과, 관광진흥과, 상급 기관에 전달하면, 별도 로그인 없이 브라우저에서 즉시 동일한 시뮬레이션 환경을 확인할 수 있습니다.
>
> 보안 고려: 공유 링크는 토큰 기반 접근이므로, 토큰을 알지 못하면 시나리오에 접근할 수 없습니다. CORS Allowlist와 CSP 정책으로 외부 도메인 접근을 차단합니다.

### Q4: 동시 접속이 많아지면 성능이 저하되지 않는가?

> A: 부하 테스트 결과로 답변드립니다.
>
> - 일반 API: 2,000+ TPS (초당 처리량) 달성, 100회 연속 요청 100% 성공
> - 캐시 Hit 시: 평균 응답 0.36ms (임계값 5ms 대비 13.9배 여유)
> - 2단계 Rate Limiter가 과부하 요청을 선제 차단하여 서버 안정성 보호
>
> 자세한 결과는 `docs/LOAD_TEST_REPORT.md`에서 확인하실 수 있습니다.

### Q5: CI/CD 자동 배포와 무중단 서비스가 가능한가?

> A: GitHub Actions 기반 CI/CD 파이프라인이 구축되어 있습니다.
>
> - CI: `main` 브랜치 Push 시 Vitest 84개 테스트 자동 실행 + 프로덕션 빌드
> - CD: SSH 접속으로 원격 Docker 컨테이너 무중단 재가동
> - 헬스체크: 배포 완료 후 `/api/scenarios`, `/api/tour/area-code` 등 4개 엔드포인트 자동 검증
> - `npm run deploy:check` 명령으로 수동 헬스체크도 가능

### Q6: 보안 인증키가 프론트엔드에 노출될 위험은 없는가?

> A: 서버 사이드 프록시 아키텍처로 완전히 차단됩니다.
>
> - TourAPI, KTDB, 관광데이터랩 등의 인증키(serviceKey)는 서버 환경변수(.env)에만 저장
> - 프론트엔드는 `/api/tour/area-code` 등 프록시 엔드포인트만 호출
