# Fest-Twin 기능설명서 초안

## 서비스명

Fest-Twin (페스트트윈)

## 서비스 유형

공공데이터 기반 B2G 축제 기획 사전 진단 웹 서비스

## 서비스 대상

- 지자체 축제 기획 담당자
- 지자체 안전관리 부서
- 지역경제·관광 활성화 담당 부서
- 공모전 심사위원 및 공공 사업 평가 담당자

## 서비스 설명

Fest-Twin은 축제 개최 전 수요 예측 실패, 경험 의존형 예산 편성, 대규모 관광객 쏠림으로 인한 만족도 저하 문제를 줄이기 위한 웹 기반 사전 진단 서비스다. 사용자가 지역, 기간, 예산, 수용 인원, 프로그램 정보를 입력하면 한국관광공사 TourAPI 기반 축제 후보와 주변 관광지 데이터를 조회하고, 검색량 기반 사전 관심도, 관광 소비 객단가, 교통량 근거를 결합해 예상 방문객, 혼잡도, 안전·물류 권고, 경제효과를 산출한다.

## 상세 기능

1. 지역·기간 기반 TourAPI 축제 후보 조회
2. 선택 축제 기반 기획안 자동 채움
3. 예상 방문객, 흥행 예측 지수, ROI, 안전·물류 KPI 산출
4. Naver DataLab 검색량 기반 사전 관심도 보정
5. 행사장 지도와 혼잡도 히트맵 시뮬레이션
6. KPI별 산출 근거 Drawer 제공
7. 시나리오 저장 및 공유 링크 복원
8. 공개검토용 보고서 출력

## 공개검토용 보고서

Fest-Twin 보고서는 단순 화면 캡처가 아니라 지자체 내부 검토와 공모전 심사자가 같은 순서로 판단할 수 있도록 구성한 출력 산출물이다. 보고서는 예측 결과, 혼잡·안전 진단, 예산·경제 효과, 사용 데이터와 한계, 개선 권고 섹션으로 나뉘며, 각 수치가 어떤 OpenAPI·백데이터·사용자 입력값·시뮬레이션 산출값을 근거로 하는지 함께 표시한다.

선택한 TourAPI 축제가 있는 경우 보고서의 데이터 섹션에 축제명, `contentId`, 기간, 주소가 유지된다. 따라서 심사자는 어떤 실제 축제 후보를 기준으로 예측했는지와 실제 조회가 실패했을 때 어떤 Fallback을 사용했는지 같은 문서에서 확인할 수 있다.

## 활용 API 정보

### 한국관광공사 TourAPI 4.0

- `areaCode2`: 지역 코드 조회
- `searchFestival2`: 지역·기간 기반 축제 후보 조회
- `detailCommon2`: 축제 상세 정보와 좌표 조회
- `locationBasedList2`: 주변 관광지 조회

### 검색량·소셜 관심도 보조 API

- Naver DataLab 통합검색어 트렌드: 축제명과 지역명 검색량 기반 사전 관심도 보정
- YouTube Data API Search: 축제 관련 영상 콘텐츠 언급 보조 지표

## 데이터 해석 한계

TourAPI는 축제 메타데이터와 관광지 정보를 제공하지만 실제 방문객 집계값을 항상 제공하지 않는다. 따라서 Fest-Twin의 예상 방문객 수는 TourAPI 메타데이터, 유사 축제·지역 백데이터, 검색량 관심도, 사용자가 입력한 예산·수용 인원·프로그램 정보를 결합한 추정값이다.

Naver DataLab 검색량은 실제 방문객 수가 아니라 개최 전 관심도 흐름을 나타내는 보조 지표다. 서비스는 이 값을 방문객 수로 직접 치환하지 않고 제한된 보정 계수로만 사용한다.

## Fallback 정책

외부 API 키가 없거나 호출이 실패해도 서비스 화면은 중단되지 않는다. 이 경우 검증 스냅샷 또는 샘플 데이터를 사용하며, 화면과 보고서에 실제 조회, 일부 보완, 샘플 대체 상태를 명확히 표시한다.

## 제출판 제외 범위

Instagram Hashtag API와 X API 실시간 연동은 권한 심사와 비용 리스크가 크기 때문에 2026년 9월 제출판에서는 완료 기능으로 포함하지 않는다. 해당 채널은 v2.0 확장 예정 기능으로 문서화한다.
