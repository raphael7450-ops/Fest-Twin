## 3. 기획 방향과 해시태그
지역·기간으로 축제를 탐색하고 선택한 행사 정보를 계획에 연결한다. 운영자는 면적·정원·예산 등의 가정을 확인하고, 하루 유입과 동시 체류를 구분한 추정 결과 및 근거를 검토한다. 데이터가 없거나 보완 자료를 사용한 경우 이를 표시한다.

제안 해시태그: #축제기획 #혼잡사전검토 #데이터근거 #운영협업
선택 과제 확인 전의 제안이며 확정된 접수 내용이 아니다.

## 5. 기능 흐름도 원고
공식 슬라이드 5를 해시태그별로 복제하고 각각 실제 화면을 첨부한다.
| 해시태그 | 화면 순서 |
| --- | --- |
| #축제기획 | 기획의 지역·시작일·종료일 입력 → 후보 보기 → 일정·출처 확인 → 선택 → 계획 확인 |
| #혼잡사전검토 | 운영 면적·동시 정원 확인 → 요약/예측 → 시간대 선택 → 밀도 근거 확인 |
| #데이터근거 | 근거 패널 → 지표 근거 → 전년도 방문객 참고 → 예측 검증 현황 |
| #운영협업 | 기획 → 시나리오 저장 → 두 계획 비교/공유 → 보고서 검토 |

공개 데모에 내부 기밀 자료를 저장하지 않는다. 기존 저장 계획의 정원·예산은 다시 확인한다.

## 6. 서비스 이미지
- 대표 이미지 1장: 서비스명과 선택 축제가 보이는 요약 화면.
- 상세 이미지 4장: 지역·기간 후보 조회, 물리 밀도 입력 조건, 데이터 근거와 검증 보류, 시나리오 비교.
- 기존 docs/assets/submission/에는 과거 또는 mock 캡처가 있으므로 최신 실데이터 증빙으로 재사용하지 않는다.
- 촬영일·릴리스·선택 축제·조회/보완 상태를 기록하고 비밀키·개인정보를 제외한다.

## 7. 한국관광공사 OpenAPI
API명: 한국관광공사 국문 관광정보 서비스 (KorService2).
areaCode2 지역 코드, searchFestival2 축제 검색, searchKeyword2 키워드 검색, detailCommon2 상세 주소·좌표, detailIntro2 운영시간, locationBasedList2 주변 관광정보를 서버 프록시로 조회한다.
오퍼레이션을 별개 데이터 상품으로 부풀려 기재하지 않는다. 제출 인증키의 개발 기간 호출 이력과 실제 화면 활용을 확인한다. 본문·Git·공개 PDF에 키를 넣지 않는다.

## 8. 기타 API·파일데이터
| 데이터 | 활용 및 한계 |
| --- | --- |
| 네이버 데이터랩 검색어 트렌드 | 상대 검색 관심도를 수요 보정에 사용한다. 절대 검색량·방문객 실측이 아니며 예측 개선 효과는 미검증이다. |
| 지역축제·전년도 방문객 파일자료 | 후보 탐색과 전년도 참고 표시. 집계 방식 미확인 자료는 정확도 평가의 승인 실적으로 사용하지 않는다. |
| 공공 버스·상권·응급의료·도시공원·관광소비 자료 | 시설과 기준월 통계를 표시한다. 시설 수를 교통 수용력·가용 병상·매출로 환산하지 않는다. 공원 전체면적은 행사 운영면적과 구분한다. |

최종 기재 시 정확한 데이터 상품명·제공기관·URL을 확인한다. 샘플 교통량·소비 원단위는 실시간 관측으로 기재하지 않는다.

## 9. 차별성과 발전계획
차별성: 축제 후보, 운영 가정, 출처, 추정 결과를 연결하여 검토 과정을 설명한다. 하루 유입·동시 체류·누적 방문객을 구분하고 면적이나 검증 자료가 없으면 판정을 보류한다.

발전계획: 출입 계수·입장권 등 정의가 명확한 실측과 사전 보관 예측을 비교한다. 동일 표본에서 전년도 기준값과 모델 오차를 평가하고 검색 보정의 추가 효과를 검증한다. 현장 파일럿 이후에만 정확도와 안전 개선 성과를 제시한다.

현재 입증하지 않은 사항: 방문객 예측 정확도, 사고 예방 효과, 투자 수익, 정부 승인, 실시간 현장 군중 관측.
