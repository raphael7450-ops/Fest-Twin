# 페스트트윈 정부용 대시보드 화면 흐름

## 목적

본 문서는 페스트트윈 MVP 대시보드가 지자체 담당자와 공모전 심사자가 어떤 순서로 서비스를 이해하도록 설계되었는지 설명한다.

## 첫 화면 구성

대시보드는 랜딩 페이지가 아니라 업무형 진단 화면으로 시작한다. 사용자는 첫 화면에서 서비스명, 공공 검토용 데모 상태, 정부 지침 반영 현황, 핵심 진단 지표를 바로 확인한다.

## 주요 업무 흐름

1. 축제 기획안 입력
   - 축제명, 개최 지역, 총예산, 예상 수용 인원을 수정한다.
   - 담당자 이름, 연락처, 개인 위치 이력 등 개인정보는 입력받지 않는다.

2. 데이터 근거 확인
   - 한국관광공사 TourAPI 형태의 공공데이터 출처를 확인한다.
   - 실제 API 키가 없어도 샘플 데이터 대체 흐름을 명시한다.
   - 소셜 트렌드는 비식별 키워드 단위 샘플임을 표시한다.

3. 수요 예측 확인
   - 예상 방문객, 피크 시간, 시간대별 방문객 분포를 확인한다.
   - 예측 신뢰도와 근거 설명은 리포트 생성 로직과 연결된다.

4. 혼잡도 시뮬레이션 확인
   - 선택한 시간대 기준으로 행사장 격자별 밀집도를 표시한다.
   - 병목 후보 지점과 밀집 사유를 함께 제시한다.

5. 기획 보완 리포트 확인
   - 흥행 가능성, 밀집 위험, 예산 낭비 위험, 만족도 저하 위험을 점수화한다.
   - 피크 프로그램 분산, 출입구 안내 인력 재배치, 부스 동선 분리, 주변 관광지 연계 코스 운영 권고를 제공한다.

## 정부 지침 반영 방식

화면은 KRDS 관점에서 과업 흐름을 먼저 드러내고, 전자정부 웹사이트 품질관리 관점에서 반응형 레이아웃과 데이터 출처 표시를 포함한다. 접근성 관점에서는 입력 레이블, 텍스트 기반 상태, 키보드 조작 가능한 기본 컨트롤을 사용한다.
