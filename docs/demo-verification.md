# 페스트트윈 데모 검증 체크리스트

## 기능 흐름

- [ ] 첫 화면에서 페스트트윈(Fest-Twin) 서비스명이 보인다.
- [ ] 정부 지침 반영 현황 영역이 보인다.
- [ ] 축제 기획안 입력 영역이 보인다.
- [ ] 데이터 근거 영역에서 TourAPI 실제 조회·샘플 대체 상태와 비개인 트렌드 샘플 설명이 보인다.
- [ ] 시간대별 수요 예측 그래프가 보인다.
- [ ] 혼잡도 시뮬레이션 히트맵이 보인다.
- [ ] 주요 리스크와 기획 보완 리포트가 보인다.
- [ ] 기획 보완 리포트 영역에 `리포트 인쇄` 버튼이 보인다.
- [ ] 시나리오 저장 영역에서 현재 기획안을 저장하고 다시 불러올 수 있다.

## 접근성·품질

- [ ] 모든 입력 필드에 보이는 레이블이 있다.
- [ ] `input`과 `select`는 키보드로 이동하고 조작할 수 있다.
- [ ] 색상만으로 상태를 설명하지 않고 텍스트 설명을 함께 제공한다.
- [ ] 모바일 화면에서 카드, 입력 필드, 그래프, 히트맵, 리포트 텍스트가 겹치지 않는다.
- [ ] TourAPI 실제 연동이 없어도 샘플 데이터 사용 상태가 설명된다.

## 공공기관 검토 관점

- [ ] 개인정보를 수집하지 않는다는 설명이 보인다.
- [ ] 공공데이터 출처와 API 장애 시 대체 흐름이 보인다.
- [ ] 예산 집행 전 검토용 리포트라는 목적이 보인다.
- [ ] SaaS, CSAP, 운영 보안은 향후 검토 항목으로 분리되어 있다.
- [ ] 지자체 담당자가 수요, 혼잡, 예산, 만족도 리스크를 한 화면에서 확인할 수 있다.
- [ ] 브라우저 인쇄 기능으로 검토용 리포트를 PDF 저장 또는 출력할 수 있다.
- [ ] 시나리오 저장은 브라우저 로컬 저장소를 사용하며 서버로 개인정보를 전송하지 않는다.

## TourAPI 실제 연동 확인

- [ ] 서버 런타임에 `TOUR_API_KEY`가 없는 상태에서 앱이 샘플 데이터 대체 사용 상태로 정상 렌더링된다.
- [ ] 브라우저에 키를 노출하지 않고 서버 런타임에만 `TOUR_API_KEY`를 제공한 상태에서 앱이 TourAPI 호출을 시도한다.
- [ ] TourAPI 호출이 성공하면 데이터 근거 패널에 실제 TourAPI 조회 성공 또는 일부 조회 및 샘플 보완 상태가 표시된다.
- [ ] TourAPI 호출이 실패해도 수요 예측, 혼잡도 시뮬레이션, 기획 보완 리포트가 유지된다.
- [ ] 실제 인증키는 Git 변경 목록에 포함되지 않는다.
- [ ] 입력 기간 직접 일치 결과가 0건이면 같은 지역의 연간 TourAPI 축제 데이터를 참고하고, 데이터 근거 패널에 기간 완화 검색 사유가 표시된다.

## 상호작용 확인

1. 총 예산을 `1200`으로 변경한다.
2. 예상 수용 인원을 `30000`으로 변경한다.
3. 진단 시간대를 `20:00`으로 선택한다.

기대 결과:

- 대시보드가 오류 없이 갱신된다.
- 수요 예측 그래프가 유지된다.
- 혼잡도 히트맵이 유지된다.
- 기획 보완 리포트가 계속 보인다.
- `리포트 인쇄` 버튼이 계속 보인다.
- 저장된 시나리오를 선택하면 예산, 수용 인원, 진단 시간대가 복원된다.
- 예산과 수용 인원만 변경할 때는 TourAPI를 다시 호출하지 않는다.
