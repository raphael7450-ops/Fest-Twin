# 페스트트윈 정부 지침 기반 설계 체크리스트

## 설계 원칙

페스트트윈은 기능을 먼저 만든 뒤 공공성을 덧붙이는 방식이 아니라, 정부 디지털서비스 지침을 설계 기준으로 삼아 MVP를 구성한다.

## 적용 기준

| 기준 | 설계 반영 | MVP 상태 |
| --- | --- | --- |
| 디지털 정부서비스 UI/UX 가이드라인(KRDS) | 첫 화면을 업무형 대시보드로 구성하고 입력-진단-리포트 흐름을 명확히 한다. | 반영 |
| 전자정부 웹사이트 품질관리 지침 | 반응형 UI, API 장애 대체, 데이터 출처와 상태 표시를 구현한다. | 준비 |
| 한국형 웹 콘텐츠 접근성 지침 2.2 | 레이블, 키보드 조작, 텍스트 상태, 모바일 겹침 방지를 반영한다. | 준비 |
| 공공부문 SaaS 이용 가이드라인 | 기관 도입 검토에 필요한 권한, 로그, 데이터 보관, 운영 항목을 향후 설계로 분리한다. | 향후 |
| 클라우드 보안인증제(CSAP) | MVP는 인증 대상 구현 전 단계이며, 실증 전 보안 통제 항목을 검토한다. | 향후 |
| 개인정보 보호 및 영향평가 | MVP는 개인정보를 수집하지 않고 축제 기획 데이터만 사용한다. | 반영 |
| 공공데이터 이용정책 | TourAPI 출처, 샘플/캐시 대체 여부, 데이터 기준 시점을 표시한다. | 반영 |

## 공공기관 검토용 설명

페스트트윈은 지자체가 축제 예산 집행 전에 기획안을 객관적으로 검토하기 위한 사전 진단 SaaS다. MVP는 개인정보를 수집하지 않고, TourAPI와 샘플 트렌드 데이터를 사용해 수요 예측과 혼잡 진단을 시연한다.
