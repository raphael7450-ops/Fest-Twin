## 3. 운영 검증 및 점검 런북 (Operations Runbook)

### 3.1 사전 점검 항목
1. 서버 응답 확인: `http://192.168.55.223:18080/` (또는 로컬 개발 서버) 접속 가능 여부 점검
2. REST API 헬스체크: `/api/scenarios` 및 `/api/tour/area-code` 정상 수신 확인
3. 네이버 지도 오버레이: 행사장 지도 패널 정상 렌더링 확인 (미연결 시 Canvas 렌더러 동작)
4. 공유 링크 복원: 선택 TourAPI 축제 기준이 있는 시나리오를 저장한 뒤 공유 링크로 접속해 `선택 TourAPI 축제 기준`, `contentId`, 축제명, 기간, 주소가 데이터 근거 패널과 보고서에 유지되는지 확인

### 3.2 공유 링크 선택 기준 검증

| 단계 | 확인 항목 | 정상 기준 |
| :--- | :--- | :--- |
| 1 | TourAPI 후보 선택 | 기획안 축제명, 주소, 기간이 선택 후보 기준으로 바뀐다. |
| 2 | 시나리오 저장 | 저장 목록에 현재 기획안이 추가되고 서버 저장 성공 시 `share_token` 기반 공유 링크가 생성된다. |
| 3 | 공유 링크 접속 | 상단에 `[공유 시나리오]` 복원 안내가 표시된다. |
| 4 | 선택 기준 유지 | 데이터 근거 패널과 보고서에 같은 `contentId`, 축제명, 기간, 주소가 표시된다. |
| 5 | Fallback 확인 | 서버 조회 실패 시에도 LocalStorage fallback 시나리오에 저장된 선택 기준이 있으면 동일하게 복원된다. |

### 3.3 장애 발생 시 비상 조치 가이드
- TourAPI/외부 API 통신 지연 발생 시: 백엔드의 10분 LRU 인메모리 캐시 및 프론트엔드의 Fallback 샘플 데이터가 자동 활성화되어 시연이 끊기지 않고 지속됩니다.
- SQLite DB 응답 불가 시: 브라우저 LocalStorage Graceful Fallback이 작동하여 시나리오 저장 및 불러오기가 정상 작동합니다.

## 4. 선택 축제 기준 공유 링크 검증

시나리오 저장 및 공유 링크 시연 시에는 단순 입력값 복원뿐 아니라 선택한 TourAPI 축제 기준이 함께 복원되는지 확인한다.

1. 지역과 기간을 선택한 뒤 `TourAPI 축제 후보 조회`를 실행한다.
2. 후보 목록에서 실제 축제를 선택하고 데이터 근거 패널의 `contentId`, 행사명, 기간, 좌표가 표시되는지 확인한다.
3. `시나리오 저장`을 누른 뒤 `공유 링크`를 새 탭에서 연다.
4. 새 탭에서 기획안, 피크 시간대, 지도 위치, 데이터 근거 패널의 TourAPI `contentId`가 기존 선택 축제와 동일한지 확인한다.
5. 이 기준이 같으면 수요 예측, 교통, 소비, 지도, 보고서 근거가 같은 축제 후보를 기준으로 재계산된 것으로 본다.
