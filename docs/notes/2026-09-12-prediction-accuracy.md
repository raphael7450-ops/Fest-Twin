# 예측 정확도 검증 결과와 실행 방법

## 실제 결과

현재 판정은 **INSUFFICIENT_EVIDENCE**다. 실적 2건은 존재하지만,
검토 완료된 입력 스냅샷과 일치하는 평가 쌍이 없어 MAE/WAPE를 계산하지 않는다.
테스트 통과 수와 예측 정확도는 다른 개념이다. 운영 예측 계수는 변경하지 않았다.

- 대전 0시축제: 기존 발표 수치는 있으나 집계 방식이 미확인이다.
- 군산 시간여행축제: 기존 공식 평가 자료는 부분 계측을 전체 기간으로
  확장한 추정치다. 모델 유입량과 공간·시간·중복 입장 기준의 일치 여부가
  검토 중이다. 이번에 공식 게시일 2026-04-15를 다시 확인했으며, 이 자료를
  2025년 행사 전 입력으로 사용하면 미래 정보 누출이다.
- 공식 2024/2025 비교 자료와 당시 모델 입력을 조사했으나 이번 조사에서
  추가로 승인할 수 있는 완전한 비교 쌍을 확보하지 못했다. 뉴스의 방문객
  숫자만으로 집계 방법이나 당시 입력을 추정해 채우지 않았다.

공식 출처: [군산시 2025 조사평가 연구용역 게시물](https://www.gunsan.go.kr/main/m82/view/9828373).
보고서 전문을 재배포하지 않으며 이용 조건은 별도 확인해야 한다.

## 추가한 검증 기능

1. `npm run replay:visitors`로 현재 운영 예측 함수를 오프라인 재실행한다.
   현재 API 조회나 샘플 입력을 자동으로 끼워 넣지 않는다.
2. SHA-256으로 확인한 입력 묶음과 사전 공개 시각, 검토 상태를 확인한다.
   입력 SHA는 변경 감지 수단이지 진위 보증이 아니다.
3. 날짜·공간·집계 단위가 검토된 누적 입장만 비교한다. 하루별 평일/주말
   모델 유입을 합산하며 고유 방문객으로 변환하지 않는다.
4. 전년도 기준 예측과 후보 모델을 **같은 실적 ID**에서만 비교한다.
   학습용, 구분 미확인, 다른 연도·기간 단위·재현 모드는 합치지 않는다.
5. MAE, WAPE, 편향, 독립 축제 수를 계산한다. 독립 축제 5개 미만은
   개선 심사도 보류한다. 5개는 통계적 정확도 인증 기준이 아니며,
   표본이 충분해도 자동 모델 교체는 하지 않는다.
6. 한국시간 행사일 자정 이후 받은 예측을 사전 예측으로 인정하지 않는다.
7. 예측·체류 계산 소스의 지문을 모델 버전에 포함해 다른 코드를 같은
   모델 성적으로 합치지 않는다. 지문 대상 파일은 CLI에 명시한다.

## 실행

```powershell
npm run replay:visitors
npm run validate:visitors
npm test
npm run build
```

기본 재현 보고서는 `reports/visitor_replay.json`이다. 비교 쌍 없음은
종료 코드 2, 입력/실행 오류는 1, 유효 비교 생성은 0이다. 코드 0도
정확도 인증이나 모델 교체 승인을 의미하지 않는다.

별도 입력 파일과 출력 파일은 다음처럼 지정한다.

```powershell
npm run replay:visitors -- data/reviewed-visitor-cases.json reports/reviewed-visitor-replay.json
```

별도 입력 파일은 자동 생성하지 않는다. 실적을 보고 기획안을 역산하면
검증이 무효가 되므로 검토된 자료가 준비된 후에만 작성해야 한다.

## 입력 계약

기존 `actuals`, `inputs`, `predictions`에 `replayCases` 배열을 추가한다.
각 case는 `id`, `actualId`, `snapshotInputId`, `baselineInputId`,
`inputCutoff`, `comparisonReview`, `evaluationRole`을 갖는다.
`comparisonReview=approved`는 사람이 공간·기간·입장 정의를 대조했다는
선언이다. 임의로 승인 값을 넣는 것은 검증이 아니다.

스냅샷 input에는 `payload={plan,tourism,trends,demandBackdata?,weather?}`,
`sha256=SHA256(JSON.stringify(payload))`, `reviewStatus=approved`,
`sourceUrl`, `year`, `availableAt`이 필요하다. 대상 연도 자료는
`kind=pre_event_snapshot`인 검토 완료 사전 입력만 허용한다. 실적은
이 예외에 해당하지 않는다. 기본 입력 누락은 모델 기본값으로 보완하지 않고
제외한다. 원래 모델의 보정계수 자체는 그대로 사용한다.

baseline input에는 전년도 `value`, `festivalId`, `unit`, `measure`,
`scope`, `geography` 및 사전 공개·검토 정보가 필요하다. 현재 baseline은
전년도 같은 집계 총량을 그대로 예측값으로 사용하는 단순 비교 모델이다.

재현 결과는 원본 근거 파일을 덮어쓰지 않는다. `generatedPredictions`는
입력·실적 검토 후 근거 원장에 반영해야 공개 대시보드 성적에 나타난다.
불완전한 재현 결과나 테스트용 합성 자료는 공개 원장에 반영하지 않는다.

## 정확도 개선을 아직 적용하지 않은 이유

모델에는 최소 5,000명 및 입력 수용인원의 1.45배 상한 등 가정이 있다.
소규모 행사와 대형 다일 행사에 적합한지 실제 holdout으로 확인해야 한다.
이 가정의 존재만으로 실제 오차율을 산출할 수는 없다. 계수 보정과
성능 개선 주장은 검토된 사전 입력·실적 확보 후 별도 단계로 남아 있다.

## 실행 검증

- 전체 테스트 653개 통과, 기존 제외 4개. TypeScript/Vite 빌드 통과.
- 실제 원장 재현 명령: 비교 가능 0건, 종료 코드 2. 결과 파일은
  `reports/visitor_replay.json`에 생성되며 검증용 합성 예측은 포함하지 않는다.
- 운영 모델을 사용한 결정론적 재현 테스트는 합성 fixture로만 실행했다.
  이 테스트 수치를 실적 정확도로 사용하지 않았다.
- 모바일 390px에서 합성 UI 응답을 로컬 브라우저에만 주입하여 표본 부족과
  오차 설명이 표시되고 가로 넘침이 없음을 확인했다. 운영 원장에는 쓰지 않았다.
