# 시간대별 수요 예측 프로파일 기준

Fest-Twin의 시간대별 수요 예측은 실제 시간대별 집계값이 아니라, 축제 성격과 기획 시간표를 반영한 사전 시뮬레이션 분포다. TourAPI 후보 또는 지역축제 DB 후보를 선택하면 축제명, 주소, 기간, 유사 백데이터 유형을 기준으로 운영 시간과 대표 프로그램 구성이 보정된다.

## 운영시간 데이터 우선순위

1. TourAPI `detailIntro2`의 `playtime`
   - 행사·축제 타입(`contentTypeId=15`)에서 공연시간 또는 운영시간이 제공되는 경우가 있다.
   - 예: `11:00~22:00`처럼 내려오면 시간대별 수요 예측 범위를 해당 운영시간 안으로 제한한다.
2. 후보 또는 DB에 저장된 운영시간 필드
   - 향후 `openingHour`, `closingHour`, `operatingTimeText`, `operatingTimeSource`, `operatingTimeConfidence`를 DB에 넣으면 이 값을 우선 사용할 수 있다.
3. 축제 유형 기반 기본값
   - 운영시간이 없을 때만 카운트다운형, 먹거리형, 주간 가족·체험형, 야간 미디어형 기본 분포를 적용한다.

## 축제 유형별 기본 분포

| 유형 | 적용 키워드 예시 | 운영 시간 예시 | 수요 집중 |
| --- | --- | --- | --- |
| 카운트다운형 | 카운트다운, 새해, 연말, 타종, 제야, 해맞이 | 18, 20, 22, 23, 24시 | 23~24시 |
| 먹거리·특산물형 | 먹거리, 음식, 푸드, 미식, 커피, 맥주, 와인, 수산물, 축산물 | 10, 12, 14, 16, 18, 20시 | 12시와 18~20시 |
| 주간 가족·체험형 | 꽃, 튤립, 벚꽃, 장미, 가족, 어린이, 체험, 주간 | 10, 12, 14, 16, 18시 | 14~16시 |
| 야간 미디어형 | 야간, 빛, 라이트, 미디어, 조명, 드론, 불꽃 | 16, 18, 20, 22시 | 20~22시 |
| 기본 프로그램형 | 위 유형에 해당하지 않는 경우 | 기존 기획 시간표 유지 | 프로그램 집객력 기준 |

## 해석 한계

전국문화축제표준데이터는 축제명, 장소, 기간, 주소, 좌표 확인에는 유용하지만 현재 확인한 응답 기준으로 운영시간 필드는 제공하지 않는다. 이 분포는 행사 전 의사결정용 예측이며 확정 방문객 집계가 아니다. 실제 운영 단계에서는 출입 카운터, 교통량, 현장 밀집도, 검색량 변화 등 실측 데이터가 확보될수록 시간대별 보정값을 업데이트해야 한다.
