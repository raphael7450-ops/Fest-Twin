# KPI 증거 매트릭스

## 목적

Fest-Twin의 주요 KPI가 어떤 데이터 근거와 계산 가정을 사용하는지 한 곳에서 확인한다. 이 문서는 심사자 설명, 기능설명서, 보고서 문구를 맞추기 위한 기준표다.

## 데이터 상태 기준

| 상태 | 의미 | 화면 표기 |
| :--- | :--- | :--- |
| `live` | 서버 프록시 또는 공개 API에서 실제 응답을 받은 상태 | 실조회 |
| `partial-fallback` | 일부 실제 응답 또는 승인 전 구조 확인값에 샘플을 보완한 상태 | 일부 보완 |
| `file-normalized` | 파일데이터를 서비스 계산 구조에 맞게 정규화한 상태 | 파일 정규화 |
| `sample-fallback` | API 키, 승인, 결과 부족, 네트워크 실패로 샘플을 사용한 상태 | 샘플 대체 |

## KPI별 근거

| KPI | 주요 데이터 근거 | Fallback 동작 | 한계 |
| :--- | :--- | :--- | :--- |
| 흥행 예측 지수 | 선택 TourAPI 축제 기준, 주변 관광지 맥락, 검색 관심도 보정, 지역 수요 백데이터, 사용자 입력값, 시뮬레이션 산출값 | 선택 후보가 없으면 현재 기획안과 TourAPI 샘플/보완 근거를 사용한다. Naver DataLab 응답이 없으면 검색 관심도 샘플로 보정한다. | 실제 방문객 확정값이 아니라 사전 의사결정용 예측값이다. |
| 최고 밀집 위험도 | 시간대별 예상 방문객, 행사장 격자, 시설 배치, 시뮬레이션 산출값 | 실측 동선 데이터가 없으면 입력된 시설 배치와 샘플 혼잡 가중치를 사용한다. | 현장 통제, 날씨, 돌발 교통 통제는 반영하지 않는다. |
| 예산 효율성 점수 | 사용자 입력 총 예산, 예상 방문객 산출값 | 예산 입력값과 예측 방문객만으로 산정한다. | 집행 항목별 세부 계약금액은 반영하지 않는다. |
| 지역 상권 유출 연계도 | 주변 관광지 맥락, 행사장 지역 입력값 | 주변 관광지 실조회가 부족하면 TourAPI 형태의 샘플 주변 지점을 사용한다. | 실제 카드 소비나 이동 동선 확정값이 아니다. |
| 안전관리 요원 추천 배치 | 피크 방문객, 최고 밀집도, 병목 후보 수, 시설 배치 | 실시간 군중 계측이 없으면 시뮬레이션 산출값을 사용한다. | 법정 안전관리 계획을 대체하지 않고 사전 검토 보조값으로만 사용한다. |
| 의료/구급 인력 추천 배치 | 피크 방문객, 임계 혼잡 격자, 시설 배치 | 실측 응급 이력 데이터가 없으면 혼잡 격자와 방문객 규모로 산정한다. | 실제 의료 인력 배치는 관할 지침과 현장 위험평가가 우선이다. |
| 주차 수용 차오름 비율 | 피크 방문객, 사용자 입력 수용 인원, 고위험 격자, KTDB/View-T 교통 근거 | KTDB/View-T 매핑이 없거나 조회가 실패하면 교통량 샘플을 사용한다. | 기준연도 도로 교통량이며 실시간 교통정보가 아니다. |
| 예산 대비 경제적 파급효과 | 예상 방문객, 사용자 입력 총 예산, 관광소비 객단가, ROI 산출값 | 지역 소비 API가 없으면 공공데이터 구조 기반 객단가 샘플을 사용한다. | 실제 매출 또는 카드 결제 실적이 아니라 예상 소비 창출액이다. |

## 화면 반영 기준

- `DataBasisPanel`은 TourAPI, 검색 관심도, 교통 근거, 관광소비, 지역 수요 백데이터의 상태를 한 줄 요약으로 표시한다.
- 근거 드로어는 KPI별 상세 원본, 입력값, 산출값을 분리해서 표시한다.
- 보고서와 대시보드는 같은 데이터 상태 명칭을 사용한다.
- 서비스키, 서버 비밀번호, 인증 토큰은 근거 항목과 보고서에 포함하지 않는다.
