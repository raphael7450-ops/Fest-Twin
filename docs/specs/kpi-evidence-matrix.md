# KPI Evidence Matrix

Fest-Twin Phase 2의 핵심 설득 포인트는 예측값 자체보다 “어떤 데이터와 가정으로 그 수치가 만들어졌는지”를 대시보드와 보고서에서 같이 보여주는 것입니다.

## 데이터 상태 라벨

| 상태 | 의미 | 화면 표시 |
| --- | --- | --- |
| `live` | 실제 API 또는 실시간 연동 성공 | 실데이터 |
| `partial-fallback` | 실제 API 일부 사용 후 샘플/보완값 결합 | 부분 보완 |
| `file-normalized` | 공공데이터 파일을 정규화해 사용 | 파일 정규화 |
| `mapped-sample` | 지역/시간 조건에 맞춘 매핑 샘플 | 지역 매핑 샘플 |
| `sample-fallback` | API 실패 또는 미연동 시 제출 데모용 샘플 | 샘플 보완 |

## KPI별 근거 매트릭스

| KPI | 주요 근거 | 보완 근거 | 한계 |
| --- | --- | --- | --- |
| 흥행 예측 지수 | 선택 TourAPI 축제 기준, 주변 관광지 맥락, 검색 관심도 보정 | 지역 수요 백데이터, 사용자 입력 수용 인원/예산/프로그램 | 실제 방문객 집계가 아니라 사전 의사결정용 추정값 |
| 최고 밀집 위험도 | 시간대별 예측 방문객, 행사장 격자, 시설 배치 | 병목 셀 개수, 피크 시간 | 현장 동선·통제선·기상 변화는 별도 반영 필요 |
| 예산 효율성 점수 | 총 예산, 예상 방문객 | 방문객 1인당 예산 산출값 | 예산 집행 세목이 세분화되면 재계산 필요 |
| 지역 상권 유출 연계도 | 주변 관광지 수와 매력도 | 행사장 주소, 지역 정보 | 실제 카드 소비 이동 경로가 아니라 연계 가능성 추정 |
| 안전관리 요원 추천 | 피크 방문객, 최고 밀집도, 병목 정보 | 격자 기반 혼잡 시뮬레이션 | 법정 배치 기준 검토와 현장 운영계획 확인 필요 |
| 의료/구급 인력 추천 | 피크 방문객, 위험 격자 수 | 혼잡도 단계 | 의료기관 거리, 구급차 진입로는 v1 이후 보강 |
| 주차 수용 차오름 비율 | 피크 방문객 기반 차량 유입 추정 | KTDB/View-T 교통 근거 | 실제 주차면 수와 대중교통 분담률 연동 필요 |
| 예산 대비 경제적 파급효과 | 예상 방문객, 관광소비 객단가, 총 예산 | 지역 관광소비 강도 | 고정 객단가가 아니라 지역/기간별 보정값으로 지속 교체 필요 |

## 구현 기준

- `DataBasisPanel`은 TourAPI, 검색/소셜 트렌드, KTDB/View-T, 관광소비, 지역 수요 백데이터의 상태를 한 번에 보여준다.
- `createMetricEvidenceSet`은 모든 상단 KPI에 최소 1개 이상의 `sourceDetails`를 제공한다.
- 수요 예측 KPI는 선택 축제, 주변 관광지, 검색 관심도, 지역 백데이터, 사용자 입력 근거를 함께 포함한다.
- 브라우저, 보고서, 문서에는 `serviceKey`, `clientSecret`, `Authorization`, `Cookie` 같은 비밀값을 노출하지 않는다.
