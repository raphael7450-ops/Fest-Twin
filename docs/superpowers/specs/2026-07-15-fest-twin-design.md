# 페스트트윈(Fest-Twin) 설계 문서

## 1. 프로젝트 맥락

페스트트윈은 2026 관광데이터 활용 공모전 웹·앱 구현 부문 지정과제 9번을 겨냥한 B2G SaaS 서비스다.

지정과제 9번의 문제는 다음과 같다.

> 축제 수요 예측 실패 및 주관적 경험 의존형 기획으로 인한 예산 낭비 리스크 존재 및 대규모 관광객 쏠림에 따른 축제 만족도 저하

페스트트윈은 이 문제를 "축제 흥행 예보 + 군중 안전 디지털 트윈"으로 해결한다. 단순히 방문객 수를 예측하는 도구가 아니라, 지자체와 축제 위탁사가 예산 집행 전에 축제 기획안을 데이터 기반으로 검증하고 보완할 수 있는 의사결정 플랫폼으로 설계한다.

서비스 정의:

> 페스트트윈은 한국관광공사 TourAPI의 전국 축제·관광지 데이터와 실시간 소셜 트렌드를 융합해 축제 수요를 사전 예측하고, 웹 기반 군중 시뮬레이션으로 행사장 혼잡도와 안전 리스크를 진단하며, 지자체 담당자에게 예산·동선·안전·프로그램 개선 리포트를 제공하는 B2G SaaS다.

## 2. 목표 사용자

주요 사용자:

- 축제 예산 집행 전 기획안을 객관적으로 검증해야 하는 지자체 관광·축제 담당자
- 지자체에 축제 기획안, 운영안, 안전계획을 제출하는 축제 위탁사 실무자

보조 사용자:

- 축제 계획의 데이터 근거를 검토하는 공공기관 관리자
- 안전, 교통, 운영, 홍보 협력사가 함께 볼 수 있는 사전 진단 자료가 필요한 실무자

## 3. 해결하려는 문제

현행 축제 기획은 과거 경험, 담당자 감각, 위탁사 제안서에 많이 의존한다. 이 방식은 다음 네 가지 리스크를 만든다.

- 수요 예측 실패: 예상 방문객 수와 피크 시간대가 객관적으로 검증되지 않는다.
- 주관적 기획: 프로그램, 인력, 부스, 홍보, 안전 배치가 개인 경험에 좌우된다.
- 예산 낭비: 수요가 낮은 프로그램에 예산이 과다 투입되거나, 안전·운영 예산이 과소 편성될 수 있다.
- 만족도 저하: 인기 콘텐츠, 출입구, 먹거리 부스, 화장실 등에 관광객이 쏠리면서 대기시간과 안전 위험이 커진다.

페스트트윈은 축제 기획안을 입력받아 데이터 기반 사전 진단과 개선 리포트로 변환함으로써 이 문제를 해결한다.

## 4. 제품 방향

승인된 MVP 방향은 통합 대시보드형이다.

기본 사용자 흐름:

1. 담당자가 축제 기획안을 입력한다.
2. 페스트트윈이 TourAPI와 소셜 트렌드 데이터로 기획안을 보강한다.
3. 수요 예측 엔진이 예상 방문객과 피크 시간대를 산출한다.
4. 군중 시뮬레이션 엔진이 행사장 혼잡도와 병목 지점을 시각화한다.
5. 리포트 엔진이 예산, 동선, 안전, 프로그램 개선안을 제안한다.

이 방향은 리포트 중심형이나 시뮬레이션 중심형보다 과제 대응력이 높다. 수요 예측 실패, 주관적 기획, 예산 낭비, 관광객 쏠림, 만족도 저하를 한 화면 흐름 안에서 모두 다룰 수 있기 때문이다.

## 5. MVP 범위

첫 구현은 정교한 물리 기반 군중 엔진보다, 심사위원이 바로 이해할 수 있는 데이터 기반 진단 흐름을 우선한다.

포함 기능:

- 축제 기획안 입력
- TourAPI 기반 주변 관광지·유사 축제 맥락 분석
- 소셜 트렌드 기반 관심도 보정
- 규칙 기반 축제 수요 예측
- 히트맵형 군중 혼잡 시뮬레이션
- 흥행 가능성, 혼잡 위험, 예산 낭비 위험, 만족도 저하 위험 점수화
- 기획 보완 리포트 생성

MVP의 목표는 생산 수준의 통계 모델을 증명하는 것이 아니다. 공공 관광 데이터와 트렌드 데이터를 활용하면 축제 기획 의사결정이 어떻게 객관화되는지 보여주는 것이다.

## 6. 핵심 화면

### 6.1 축제 기획안 입력 화면

목적: 사전 진단에 필요한 축제 정보를 수집한다.

입력 항목:

- 축제명
- 개최 지역과 행사장 주소
- 개최 기간과 운영 시간
- 총 예산, 홍보 예산, 안전 운영 예산
- 주요 프로그램과 시간표
- 주요 타깃 방문객: 가족, 청년, 외국인, 지역민 등
- 행사장 구성: 출입구, 메인 무대, 부스, 화장실, 주차장, 응급 부스, 휴게 공간
- 홍보 키워드: 벚꽃, 야시장, K-POP, 먹거리, 전통문화 등

MVP 단순화:

- 사용자는 샘플 축제 기획안으로 바로 시작할 수 있다.
- 행사장 배치는 정밀 GIS가 아니라 단순 2D 격자 또는 평면도 기반으로 표현한다.
- 프로그램 시간표는 간단한 표 형태로 입력한다.

### 6.2 진단 대시보드

목적: 공공 담당자가 축제 기획안의 상태를 즉시 파악하게 한다.

상단 요약 지표:

- 예상 방문객 수
- 흥행 가능성
- 혼잡 위험도
- 예산 낭비 위험도
- 만족도 저하 위험도

주요 영역:

- 시간대별 방문객 예측 그래프
- 행사장 혼잡 히트맵
- 주요 리스크 Top 5
- 우선 개선 과제

예시 리스크 문구:

- 19:00 메인 공연 직전 중앙 무대 주변 혼잡 위험이 높다.
- 1번 출입구에 전체 유입의 대부분이 집중될 가능성이 있다.
- 먹거리 부스 밀집 구역에서 대기시간이 증가할 수 있다.
- 홍보 예산 대비 예상 수요 증가폭이 낮다.
- 가족 단위 방문객 비중에 비해 휴게 공간이 부족하다.

### 6.3 디지털 트윈 시뮬레이션 화면

목적: 군중 위험을 시각적으로 이해시키고 데모 임팩트를 만든다.

MVP 시뮬레이션 방식:

- 방문객은 설정된 출입구를 통해 유입된다.
- 방문객은 수요 예측 결과에 따라 시간대별로 분배된다.
- 무대, 부스, 화장실, 주차장 등 주요 시설은 관심도 가중치를 가진다.
- 격자 기반 히트맵으로 밀집도를 보여준다.
- 출입구, 동선, 인기 시설 주변 밀집도가 기준치를 넘으면 병목 지점으로 표시한다.

제어 요소:

- 시간대 슬라이더
- 시나리오 선택: 기본안, 프로그램 시간 조정, 출입구 분산, 부스 재배치
- 리스크 표시 켜기/끄기

제품 표현은 "실시간 물리 기반 군중 시뮬레이션"이 아니라 "웹 기반 혼잡도 시뮬레이션 및 안전 리스크 진단"으로 잡는다. 이렇게 해야 MVP 구현 범위와 서비스 설명이 일치한다.

### 6.4 기획 보완 리포트 화면

목적: 진단 결과를 실제 기획 수정안으로 바꾼다.

리포트 구성:

- 종합 진단
- 수요 예측 근거
- 혼잡·안전 리스크
- 예산 낭비 리스크
- 방문객 만족도 저하 요인
- 추천 개선안
- 기대 효과

예시 개선안:

- 메인 공연 시간대에 인근 보조 프로그램을 배치해 관람객을 분산한다.
- 1번 출입구 주변에 임시 안내 사인과 안전 인력을 추가한다.
- 먹거리 부스를 메인 무대 접근 동선에서 분리한다.
- 가족 방문객 비중이 높으므로 휴게 공간과 화장실 안내를 보강한다.
- 인근 TourAPI 관광지를 사전·사후 연계 코스로 추천해 방문 시간을 분산한다.

## 7. 데이터 소스

### 7.1 한국관광공사 TourAPI

TourAPI는 공모전 필수 활용 데이터이므로 서비스 흐름에서 명확히 드러나야 한다.

활용 가능한 데이터 범주:

- 지역 기반 관광정보
- 위치 기반 관광정보
- 키워드 검색
- 행사·축제 정보
- 숙박 정보
- 공통 정보와 소개 정보
- 이미지 정보

페스트트윈에서의 활용:

- 행사장 주변 관광지 식별
- 유사 축제 또는 인근 축제 비교
- 지역 관광 매력도 산출
- 방문 시간 분산을 위한 연계 관광 코스 추천
- 리포트 내 데이터 근거 제시

### 7.2 소셜 트렌드 데이터

MVP에서는 특정 제공자 하나에 종속되지 않는 플러그형 구조로 설계한다.

가능한 입력:

- 검색 트렌드 지수
- 소셜 미디어 키워드 언급량
- 블로그·뉴스 키워드 언급량
- 긍정·부정 신호 비율
- 지역·계절 키워드 관심도

페스트트윈에서의 활용:

- 기본 수요 예측값 보정
- 급상승 테마 감지
- 홍보 키워드 적합도 평가
- 프로그램 기획과 현재 관심사의 불일치 탐지

### 7.3 사용자 입력 기획 데이터

사용자 입력값은 진단의 기준점이다.

중요 항목:

- 예산
- 기간과 운영 시간
- 프로그램 시간표
- 행사장 수용력 추정치
- 주요 시설 배치
- 타깃 방문객
- 홍보 키워드

## 8. 수요 예측 로직

MVP의 수요 예측은 설명 가능한 규칙 기반 모델로 시작한다.

입력:

- TourAPI 주변 관광지 기반 지역 관광 매력도
- 유사 축제·행사 수와 성격
- 계절성, 주말, 공휴일 등 날짜 요인
- 프로그램 매력도
- 소셜 트렌드 관심도
- 홍보 키워드 적합도
- 행사장 접근성과 수용력

출력:

- 총 예상 방문객 수
- 시간대별 예상 방문객 수
- 피크 시간대
- 흥행 가능성 점수
- 예측 신뢰도

MVP 예측식:

```text
기본 수요 =
  지역 관광 매력도
  * 계절성 계수
  * 프로그램 매력도
  * 소셜 관심도 계수
  * 접근성 계수

예상 방문객 =
  기본 수요를 예산 규모, 행사 기간, 유사 축제 기준값으로 보정
```

대시보드는 점수만 보여주지 않고, 어떤 요인이 결과에 영향을 줬는지 함께 보여줘야 한다. 공공기관 사용자는 결과의 설명 가능성을 중요하게 보기 때문이다.

## 9. 군중 시뮬레이션 로직

MVP 시뮬레이션은 격자 기반 밀집도 모델을 사용한다.

입력:

- 시간대별 예상 방문객
- 행사장 격자 크기
- 출입구 위치
- 주요 시설 위치: 무대, 부스, 화장실, 주차장, 응급 부스, 휴게 공간
- 시설별 관심도 가중치
- 이동 제한 구역 또는 막힌 동선

처리 과정:

1. 시간대별 방문객을 각 출입구로 배분한다.
2. 프로그램 시간표와 시설 가중치에 따라 방문객을 주요 지점으로 분배한다.
3. 격자별 밀집도를 계산한다.
4. 기준치를 넘는 구역을 병목 지점으로 표시한다.
5. 밀집도를 낮음, 보통, 높음, 매우 높음 등급으로 변환한다.

출력:

- 시간대별 혼잡 히트맵
- 병목 지점
- 안전 위험 점수
- 배치 변경 추천안

## 10. 진단 점수 체계

페스트트윈은 네 가지 사용자 노출 점수를 사용한다.

### 10.1 흥행 가능성 점수

요인:

- 유사 축제 수요
- 주변 관광지 매력도
- 소셜 관심도
- 프로그램 다양성
- 날짜와 계절 적합도

### 10.2 혼잡 위험 점수

요인:

- 예상 방문객 대비 행사장 수용력
- 출입구 집중도
- 메인 무대·부스 집중도
- 피크 시간대 집중도
- 시설 간 간격

### 10.3 예산 낭비 위험 점수

요인:

- 예상 수요 대비 총 예산 규모
- 소셜 관심도와 예상 수요 증가폭 대비 홍보 예산
- 혼잡 위험 대비 안전 운영 예산
- 예상 방문객 분포 대비 프로그램 수와 배치

### 10.4 만족도 저하 위험 점수

요인:

- 예상 대기시간 대리 지표
- 혼잡 구역 수
- 화장실과 휴게 공간 접근성
- 이동 동선 복잡도
- 타깃 방문객과 편의시설의 불일치

## 11. 시스템 구조

MVP는 단순한 웹 구조로 구현할 수 있다.

프론트엔드:

- 통합 대시보드 UI
- 축제 기획안 입력 폼
- 2D 행사장 배치 편집기 또는 프리셋 선택기
- 히트맵 시뮬레이션 캔버스
- 리포트 화면

백엔드:

- TourAPI 연동 서비스
- 소셜 트렌드 데이터 수집 어댑터
- 수요 예측 서비스
- 군중 시뮬레이션 서비스
- 리포트 생성 서비스

저장 데이터:

- 축제 기획안
- TourAPI 응답 캐시
- 트렌드 스냅샷
- 예측 결과
- 시뮬레이션 시나리오
- 생성 리포트

데이터 흐름:

```text
사용자 기획안
  -> TourAPI 데이터 보강
  -> 소셜 트렌드 데이터 보강
  -> 수요 예측
  -> 군중 시뮬레이션
  -> 리스크 점수화
  -> 개선 리포트 생성
  -> 대시보드와 리포트 출력
```

## 12. 오류 처리와 대체 흐름

TourAPI 호출 실패:

- 캐시 데이터 또는 샘플 데이터를 사용한다.
- 결과 화면에 캐시 또는 샘플 관광 맥락을 사용했다고 표시한다.

트렌드 데이터 수집 실패:

- TourAPI와 사용자 입력값만으로 예측을 실행한다.
- 트렌드 반영 신뢰도를 낮음으로 표시한다.

행사장 배치 정보 부족:

- 축제 유형에 맞는 기본 행사장 템플릿을 사용한다.
- 사용자에게 출입구와 메인 무대 위치만 우선 확인받는다.

예측 신뢰도 낮음:

- 신뢰도와 부족한 입력 항목을 표시한다.
- 어떤 데이터를 보완하면 진단이 개선되는지 안내한다.

## 13. 테스트와 평가 기준

기능 테스트:

- 축제 기획안을 입력하고 저장할 수 있다.
- TourAPI 보강 단계가 주변 관광지 또는 대체 데이터를 반환한다.
- 수요 예측 엔진이 예상 방문객과 시간대별 방문객을 반환한다.
- 시뮬레이션 엔진이 히트맵 셀과 병목 지점을 반환한다.
- 리포트 엔진이 리스크 근거와 연결된 개선안을 반환한다.

시나리오 테스트:

- 소규모 지역 먹거리 축제
- 대형 음악 축제
- 가족 대상 문화 축제
- 출입구가 제한된 야시장

데모 성공 기준:

- 심사위원이 TourAPI 활용 지점을 명확히 이해할 수 있다.
- 심사위원이 수요 예측 방식과 결과를 볼 수 있다.
- 행사장 혼잡 시뮬레이션이 시각적으로 드러난다.
- 기획 보완 리포트가 실제 실행 가능한 개선안을 제공한다.
- 서비스가 예산 집행 전 지자체와 축제 위탁사를 위한 도구임이 분명하다.

## 14. MVP 비범위

다음 항목은 MVP에 포함하지 않는다.

- CCTV 또는 센서 기반 실시간 군중 모니터링
- 법적 효력을 갖는 안전 인증
- 정밀 GIS 수준의 행사장 모델링
- 운영 환경 수준의 머신러닝 수요 예측 모델
- 공공 조달 또는 예산 승인 자동화 워크플로

이 항목들은 향후 확장 가능하지만, 공모전 MVP의 필수 범위는 아니다.

## 15. 향후 확장

- 이동통신 또는 유동인구 데이터 연동
- 날씨 기반 수요 보정
- 대중교통과 주차 혼잡 예측
- 지역 내 여러 축제를 함께 보는 포트폴리오 계획
- 공공 보고용 PDF 내보내기
- 기존안과 개선안의 시나리오 비교
- 행사 종료 후 실제 방문객 데이터를 반영한 예측 모델 개선

## 16. 포지셔닝 문장

페스트트윈은 다음 문장으로 설명한다.

> 페스트트윈은 지자체가 축제 예산을 집행하기 전에 수요를 예측하고, 군중 위험을 시뮬레이션하며, 데이터 기반 보완안을 도출하도록 돕는 사전 축제 기획 진단 SaaS다.

이 포지셔닝은 공모전 지정과제의 핵심 문제를 직접 겨냥하면서, 디지털 트윈 시뮬레이션을 명확한 차별점으로 만든다.
