# 최종 제출 패키지 설계

## 목적

공모전 제출 직전에 필요한 URL, 제출 문구, 검증 결과, 화면 증빙, 운영 주의사항을 한곳에 모아 제출자가 빠르게 확인하고 복사할 수 있는 최종 제출 패키지를 만든다.

## 현재 상태

- 공개 데모: `https://cwserver.tail97dbc3.ts.net/`
- GitHub 저장소: `https://github.com/raphael7450-ops/Fest-Twin`
- 앱 대시보드에는 `제출 데모 검증 현황` 패널이 배포되어 있다.
- 제출 요약서, 제출 시연 가이드, 공모전 제출용 문구, 데모 검증 체크리스트가 존재한다.
- 화면 증빙 이미지는 `docs/assets/submission/`에 정리되어 있다.

## 추천 접근

문서 중심 제출 패키지를 만든다.

- `docs/final-submission-package.md`: 제출 폼에 넣을 URL, 작품명, 한 줄 소개, 짧은 소개글, 상세 소개글, 검증 요약, 화면 증빙 목록을 한 문서에 정리한다.
- `docs/final-submission-checklist.md`: 제출 전 확인해야 할 항목을 체크리스트로 정리한다.
- `artifacts/fest-twin-submission-package.zip`: 핵심 제출 문서와 화면 증빙 이미지를 압축한다.

이 방식은 앱 기능을 더 바꾸지 않고 제출 준비물을 즉시 사용할 수 있게 한다.

## 대안과 선택 이유

### 1. 문서와 압축본 중심 패키지

가장 빠르고 제출 실무에 바로 쓸 수 있다. 제출 폼 입력값과 증빙 자료가 분리되지 않아 누락 위험을 줄인다. 이번 단계에서 이 방식을 선택한다.

### 2. 발표자료 또는 PDF 생성

시각적으로 보기 좋지만 레이아웃 검수와 파일 변환 시간이 추가된다. 공모전 제출 폼이 텍스트와 이미지 업로드 중심이면 과하다.

### 3. 앱 안에 제출 안내 화면 추가

심사자에게는 유용할 수 있지만 이미 상단 검증 패널을 추가했기 때문에 지금 단계에서는 중복이다.

## 포함 범위

- 제출용 최종 문서 작성
- 제출 전 체크리스트 작성
- 기존 제출 문서와 화면 증빙을 묶은 zip 생성
- 공개 URL, TourAPI 프록시, 모바일/데스크톱 검증 상태 재확인

## 제외 범위

- 앱 UI 추가 변경
- 공개 URL 변경
- TourAPI 키 변경
- 발표자료 디자인
- 영상 제작

## 검증 기준

- 최종 제출 문서가 공개 데모 URL을 첫 번째 확인 URL로 제공한다.
- 내부 데모 URL은 보조 정보로만 제공한다.
- 제출 문구가 기존 `docs/contest-submission-copy.md`와 충돌하지 않는다.
- 압축본에 실제 비밀값이 들어가지 않는다.
- 압축본에 핵심 문서와 스크린샷이 포함된다.
- 공개 데모와 TourAPI 프록시가 계속 정상 응답한다.
