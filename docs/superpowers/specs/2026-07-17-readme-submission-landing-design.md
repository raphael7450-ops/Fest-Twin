# README 제출 랜딩 보강 설계

## 목표

공개 GitHub 저장소 첫 화면에서 심사자가 데모 URL, 제출 패키지, 핵심 문서, 병합 이력을 바로 찾을 수 있게 README 상단을 보강한다.

## 배경

최종 제출 패키지와 zip 파일은 준비되어 있고 저장소도 공개 상태다. 다만 README 상단은 제출 패키지와 최신 PR 이력을 충분히 강조하지 않아, 외부 심사자가 저장소에 들어왔을 때 어떤 링크를 먼저 봐야 하는지 한눈에 알기 어렵다.

## 범위

- README 상단의 `빠른 데모 확인` 섹션을 `제출 바로가기` 중심으로 재구성한다.
- 공개 데모, GitHub 저장소, 최종 제출 패키지, 제출 체크리스트, 제출 zip, 제출 요약서, 시연 가이드를 상단에 배치한다.
- 병합된 PR 이력은 #1부터 #5까지 최신 상태로 표시한다.
- 기존 상세 설명, TourAPI 보안 설명, 정부 지침 기반 설계 설명은 유지한다.

## 비범위

- 앱 UI 또는 서버 동작은 변경하지 않는다.
- 제출 zip 파일 내용은 변경하지 않는다.
- 새로운 배포나 Docker 이미지 생성은 하지 않는다.

## 검증

- README 링크 대상 파일이 실제로 존재하는지 확인한다.
- GitHub 저장소와 공개 데모 URL이 HTTP 200을 반환하는지 확인한다.
- 문서 변경만 있으므로 앱 테스트는 변경 위험이 낮지만, 저장소 상태와 링크 검증은 수행한다.
