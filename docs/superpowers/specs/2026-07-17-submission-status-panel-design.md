# 제출 데모 검증 패널 설계

## 목적

공개 데모 대시보드를 처음 여는 심사자가 Fest-Twin이 제출용으로 검증된 공개 데모라는 점을 즉시 이해하도록 상단 검증 패널을 추가한다. 기존 예측·혼잡·리포트 기능은 그대로 유지하고, 제출 상태와 공개 URL, TourAPI 프록시, 보안 원칙을 첫 화면에서 확인할 수 있게 한다.

## 현재 상태

- 공개 데모 URL: `https://cwserver.tail97dbc3.ts.net/`
- 내부 데모 URL: `http://192.168.55.223:18080/`
- TourAPI 프록시는 서버의 `/api/tour/*` 경로에서 동작한다.
- `README.md`, 제출 요약서, 제출용 문구, 시연 가이드에는 공개 데모와 검증 결과가 문서화되어 있다.
- 앱 화면에는 `공공 검토용 데모`, `정부 지침 반영 현황`, `데이터 근거`가 있으나 공개 제출 검증 상태를 한곳에 요약하는 UI는 없다.

## 추천 접근

`GovernmentHeader` 아래, `GovernmentReadinessPanel` 위에 새 컴포넌트 `SubmissionStatusPanel`을 추가한다.

이 위치는 사용자가 첫 화면을 열자마자 볼 수 있고, 기존 업무형 대시보드 흐름을 방해하지 않는다. 패널은 네 가지 검증 항목을 카드 형태로 보여준다.

- 공개 데모: `cwserver.tail97dbc3.ts.net` HTTPS 공개 URL
- TourAPI 프록시: `festivals/detail resultCode=0000 확인`
- 보안: `인증키는 서버 런타임 환경변수로만 주입`
- 제출 상태: `문서·스크린샷·공개 URL 검증 완료`

## 대안과 선택 이유

### 1. 상단 검증 패널 추가

장점은 심사자가 앱만 열어도 제출 준비 상태를 바로 확인할 수 있다는 점이다. 기존 컴포넌트 구조와 맞고, 테스트도 화면 텍스트 검증으로 단순하다. 이번 단계에서 이 방식을 선택한다.

### 2. 기존 헤더 문구만 보강

가장 작게 바꿀 수 있지만, TourAPI·보안·문서 검증 상태를 담기에는 정보량이 부족하다.

### 3. 별도 제출 모드 또는 탭 추가

제출 중심 화면을 분리할 수 있지만, 라우팅이나 상태 전환이 필요해 현재 MVP 단계에는 과하다.

## 컴포넌트 설계

새 파일 `src/components/SubmissionStatusPanel.tsx`를 만든다. 컴포넌트는 props 없이 정적 제출 검증 상태를 렌더링한다. 공개 URL은 클릭 가능한 링크로 제공하고, 링크에는 `target="_blank"`와 `rel="noreferrer"`를 사용한다.

패널은 기존 `panel`, `panel-heading` 스타일을 재사용하고, 내부에는 `submission-status-grid`와 `submission-status-card` 클래스를 둔다. 기존 카드 반경 8px 규칙을 따른다.

## 데이터와 보안

컴포넌트에는 실제 TourAPI 키, SSH 비밀번호, Tailscale 인증 정보 등 비밀값을 넣지 않는다. 공개 URL과 검증 상태만 화면에 표시한다.

## 테스트

`src/App.test.tsx`의 기본 렌더링 테스트에 다음 문구를 추가로 검증한다.

- `제출 데모 검증 현황`
- `공개 데모`
- `TourAPI 프록시`
- `인증키는 서버 런타임 환경변수로만 주입`

## 배포

구현 후 다음을 검증한다.

- `npm test`
- `npm run build`
- 공개 데모 URL HTTP 200
- Docker 이미지 재빌드 및 `fest-twin-demo` 컨테이너 교체
- 공개 URL에서 새 패널 텍스트 확인

## 완료 기준

- 상단에 제출 검증 패널이 표시된다.
- 모바일에서도 카드가 한 열로 정리되고 가로 넘침이 없다.
- 기존 정부 지침, 데이터 근거, 예측, 히트맵, 리포트 흐름이 유지된다.
- 테스트와 빌드가 통과한다.
- 서버 공개 데모가 새 UI를 제공한다.
