# 대시보드 시각 고도화 설계

## 배경

Fest-Twin 대시보드는 TourAPI 근거, 축제 기획 입력, 수요 예측, 지도, 혼잡 시뮬레이션, 리포트까지 기능 흐름은 갖췄다. 다만 현재 화면은 카드와 패널이 단순하게 나열되어 있어 심사자가 첫 화면에서 “정부용 B2G SaaS”의 신뢰감과 “관제형 분석 도구”의 즉시성을 동시에 느끼기에는 부족하다.

이번 개선은 무료 Figma 대시보드 레퍼런스의 구조적 장점만 차용한다. Figma 공식 템플릿 페이지는 대시보드용 컴포넌트, 스타일, 차트 템플릿을 제공한다고 설명하고, Themeberg Figma Admin Dashboard는 무료 오픈소스 Figma 관리 화면 키트로 버튼, 배지, 내비게이션, 오토레이아웃, 모바일 예시를 포함한다. TailAdmin의 2026 대시보드 UI 키트 정리에서도 무료·오픈소스 관리 화면 키트와 개발 친화적 구조, 반응형 레이아웃을 주요 기준으로 소개한다. 정부 디자인 시스템 목록은 접근성, 모바일 친화성, 사람 중심 설계를 정부 웹서비스의 핵심 원칙으로 정리한다.

## 목표

- 첫 화면을 “공공기관 검토용 사전 진단 SaaS”처럼 더 신뢰감 있게 만든다.
- 지도, 수요 예측, 혼잡도 영역은 관제센터처럼 빠르게 읽히게 만든다.
- 입력, 데이터 근거, 리포트는 담당자 업무 화면처럼 차분하고 촘촘하게 정리한다.
- 기존 기능과 데이터 흐름은 유지하고 스타일, 배치, 컴포넌트 위계를 중심으로 개선한다.
- 모바일에서도 입력, KPI, 지도, 리포트가 겹치거나 깨지지 않게 한다.

## 선택한 방향

방향은 `A+B 혼합형`이다.

- A: 공공기관 SaaS형. 흰색·차분한 회색·남색 기반의 안정된 업무 화면, 명확한 출처와 상태 배지, 촘촘한 카드 구조.
- B: 데이터 관제센터형. 중앙 지도·혼잡·예측 영역에 시각적 무게를 두고, KPI 숫자와 위험 상태를 먼저 읽히게 하는 화면.

스타트업 SaaS형의 장식적 히어로, 큰 마케팅 문구, 과한 그라데이션은 사용하지 않는다. 공모전 심사자가 기능을 빠르게 검토하는 데 방해되기 때문이다.

## 레이아웃 설계

상단은 단순 소개가 아니라 `검토 헤더`로 바꾼다. 서비스명, 과제 성격, 공공 검토 상태, 데이터 출처, 보안 원칙을 한 덩어리로 보여준다.

KPI 영역은 4개 핵심 판단값을 동일한 카드 구조로 보여준다.

- 예상 방문객
- 흥행 가능성
- 혼잡 위험도
- 예산 대비 위험

본문은 기존 3열 구조를 유지하되, 시각 위계를 강화한다.

- 좌측: 기획안 입력, 시나리오 저장, 데이터 근거
- 중앙: 시간대별 수요 예측, 실제 행사장 지도, 혼잡도 시뮬레이션
- 우측: 리스크 점수, 보완 권고, 리포트

중앙 열은 기존보다 넓고 선명하게 보이도록 카드 그림자, 제목 행, 데이터 배지를 정리한다. 지도는 화면 안에서 “실제 행사장 확인”이라는 목적이 바로 보이게 유지한다.

## 시각 시스템

- 배경: 차가운 회색 계열의 업무용 배경
- 주요 색: 남색, 청록, 파랑
- 위험 색: 빨강, 주황, 노랑을 단계적으로 사용
- 카드: 8px 이하 둥근 모서리, 얇은 테두리, 약한 그림자
- 글꼴: 기존 Inter/Pretendard 계열 유지
- 버튼: 주요 행동은 남색/청록, 보조 행동은 테두리 버튼
- 상태 배지: 데이터 출처, 검증 상태, 위험 등급을 짧고 명확하게 표시

## 접근성 및 정부 지침 관점

- 색만으로 위험 상태를 전달하지 않고 텍스트 라벨을 함께 유지한다.
- 카드 제목과 보조 설명을 분리해 스크린리더와 시각 사용자가 모두 이해하기 쉽게 한다.
- 버튼과 select/input의 높이를 일정하게 유지한다.
- 모바일에서 3열 구조는 1열로 접히며, 텍스트와 버튼이 겹치지 않게 한다.
- 데이터 출처와 fallback 상태는 계속 화면에 표시한다.

## 구현 범위

이번 단계는 화면 시각 고도화에 집중한다.

- `GovernmentHeader`의 문구와 메타 정보 구조 개선
- `SummaryCards`의 KPI 카드 위계 개선
- `styles.css`의 색상 토큰, 패널, 그리드, 입력, 카드, 반응형 스타일 개선
- 기존 TourAPI, 지도, 예측, 시뮬레이션 로직은 변경하지 않음

## 검증 기준

- 기존 테스트가 통과한다.
- 빌드가 성공한다.
- 로컬 화면에서 상단 헤더, KPI, 좌·중·우 레이아웃이 깨지지 않는다.
- 모바일 폭에서도 카드와 입력 요소가 겹치지 않는다.
- Git에는 실제 API 키와 secret이 포함되지 않는다.
