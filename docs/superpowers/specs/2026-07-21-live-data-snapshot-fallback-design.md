# 실데이터 우선 데모와 검증 스냅샷 fallback 설계

## 배경

Fest-Twin은 관광데이터 활용 공모전 제출용 B2G SaaS MVP로, 심사자가 실제 공공데이터 활용 여부를 한눈에 확인할 수 있어야 한다. 동시에 시연 당일 TourAPI 응답 지연, 축제 검색 결과 부족, 인증 문제, 지도 API 설정 문제로 핵심 화면이 깨지면 안 된다.

현재 서비스는 한국관광공사 TourAPI 프록시와 샘플 fallback 구조를 이미 갖고 있으며, 기본 데모 축제는 TourAPI 실제 조회 예시인 `강남 미디어 윈터페스타`를 사용한다. 이번 설계는 이 구조를 더 명확하게 정리해 “실시간 실데이터 우선, 검증 스냅샷 보완, 샘플 최후 fallback” 흐름으로 발전시키는 것을 목표로 한다.

## 목표

- 데모 첫인상을 “실제 관광 공공데이터 기반 서비스”로 강화한다.
- 실시간 TourAPI 조회가 성공하면 실제 응답을 화면과 리포트의 1차 근거로 사용한다.
- 실시간 조회가 실패하거나 응답이 부족하면 최근 검증한 실제 데이터 스냅샷으로 자연스럽게 전환한다.
- 샘플 데이터는 API와 스냅샷 모두 사용할 수 없을 때의 최후 fallback으로만 사용한다.
- 모든 데이터 상태를 화면에 명시해 정부 지침 관점의 출처 표시, 장애 대응, 투명성을 유지한다.

## 권장 접근

권장 방식은 3단계 데이터 우선순위다.

1. `live-tourapi`: 서버 프록시를 통한 TourAPI 실시간 조회 성공
2. `verified-snapshot`: 최근 날짜에 실제 TourAPI로 검증한 축제·관광지 스냅샷
3. `sample-fallback`: 앱 흐름 유지를 위한 공공데이터 형태의 샘플

이 방식은 데모의 설득력과 안정성을 함께 확보한다. 전부 샘플이면 공모전 주제 적합성이 약해 보이고, 전부 실시간 API에 의존하면 시연 리스크가 커진다.

## 화면 표시 원칙

데이터 근거 패널에는 항상 다음 정보를 보여준다.

- 데이터 상태: `실제 TourAPI 조회 성공`, `검증 스냅샷 사용`, `샘플 데이터 대체 사용`
- 데이터 출처: 한국관광공사 TourAPI, 검증 스냅샷 생성 기준, 샘플 보완 사유
- 기준 시점: 실시간 조회 시각 또는 스냅샷 검증 일시
- 보완 사유: API 호출 실패, 응답 부족, 기간 직접 일치 0건, 인증키 미설정 등

문구는 심사자가 오해하지 않도록 “실시간”과 “검증 스냅샷”을 분리해서 표현한다.

## 데이터 흐름

사용자가 축제명, 지역, 기간, 예산, 예상 수요를 입력하면 클라이언트는 기존처럼 서버의 `/api/tour/*` 프록시만 호출한다. 브라우저에는 TourAPI 인증키를 노출하지 않는다.

프록시 조회 결과가 충분하면 `live-tourapi` 상태로 예측과 혼잡 진단에 사용한다. 조회 실패, 빈 결과, 좌표 부족, 주변 관광지 부족처럼 실데이터만으로 화면 구성이 불안정한 경우에는 `verified-snapshot` 데이터를 병합하거나 대체한다. 스냅샷도 사용할 수 없는 경우에만 기존 샘플 fallback을 사용한다.

## 스냅샷 데이터

검증 스냅샷은 실제 TourAPI 조회 결과에서 가져온 공개 데이터만 저장한다. 인증키, 서버 비밀번호, 개인 정보, 비공개 토큰은 저장하지 않는다.

초기 스냅샷 후보는 현재 데모 축제인 `강남 미디어 윈터페스타`다.

- 축제명: 강남 미디어 윈터페스타
- 주소: 서울특별시 강남구 영동대로 511 (삼성동)
- 좌표: 127.0610512042, 37.5103955843
- TourAPI contentid: 3439947
- 검증 기준: 2026년 서울 축제 조회 결과

## 예외 처리

- TourAPI 인증키가 없으면 즉시 스냅샷 또는 샘플 fallback으로 전환한다.
- TourAPI 응답 코드가 정상이 아니면 실패 사유를 provenance에 기록한다.
- 결과는 있으나 좌표·주소·주변 관광지 정보가 부족하면 `partial-fallback` 또는 `verified-snapshot` 보완으로 표시한다.
- 지도 API 인증 실패는 축제 수요 예측 실패로 취급하지 않고, 지도 패널에서 별도 상태로 표시한다.

## 테스트 기준

- 실시간 TourAPI 성공 시 `실제 TourAPI 조회 성공` 상태가 표시된다.
- TourAPI 실패 시 샘플로 바로 가지 않고 검증 스냅샷을 우선 사용한다.
- 스냅샷 사용 시 화면에 `검증 스냅샷 사용`과 검증 기준 시점이 표시된다.
- 샘플 fallback은 최후 단계에서만 표시된다.
- 브라우저 번들에 TourAPI 인증키나 네이버 client secret이 포함되지 않는다.

## 범위

이번 설계는 데이터 근거와 데모 안정성 개선에 집중한다. 예측 모델 자체를 고도화하거나 실시간 소셜 API를 새로 붙이는 작업은 별도 단계로 분리한다.
