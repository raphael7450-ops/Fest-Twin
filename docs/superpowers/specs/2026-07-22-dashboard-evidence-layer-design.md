# Fest-Twin 대시보드 데이터 설득력 강화 설계

## 배경

Fest-Twin 대시보드는 축제 수요 예측, 혼잡도, 안전 인력, 예산 대비 효과를 한 화면에서 보여준다. 현재 화면은 결과 수치를 빠르게 이해하기에는 좋지만, 심사자나 지자체 담당자가 “이 숫자가 왜 이렇게 나왔는지”를 확인하기에는 근거 설명이 부족하다.

정부 사업형 B2G SaaS에서는 예측값 자체보다 다음 네 가지가 함께 보여야 설득력이 생긴다.

- 데이터 출처: 어떤 공공데이터와 입력값을 사용했는가
- 산출 방식: 어떤 요인이 어떤 지표에 반영되었는가
- 신뢰도: 실데이터, 일부 보완 데이터, 샘플 데이터 중 무엇인가
- 한계: 실제 집계값이 아닌 사전 예측값이라는 점을 어디까지 설명하는가

## 목표

대시보드와 리포트에서 주요 수치의 출처, 산식, 가정, 한계를 확인할 수 있도록 “근거 레이어”를 추가한다. 사용자는 화면을 벗어나지 않고 각 지표의 산출 근거를 확인할 수 있고, 제출 문서에서는 동일한 기준을 더 자세한 방법론으로 설명한다.

## 비교한 접근

### 접근 A: 대시보드 내부 근거 레이어

각 KPI, 혼잡도, 안전 인력, ROI 지표에 `근거 보기`를 붙이고, 클릭하면 사이드 패널에서 산출 근거를 보여준다.

장점은 데모 중 설득력이 가장 좋다는 점이다. 단점은 화면이 복잡해질 수 있으므로 기본 화면에는 짧은 요약만 두고 상세는 접힘 패널로 처리해야 한다.

### 접근 B: 방법론 문서 중심 보강

`docs/data-methodology.md`에 지표 정의, 산식, 데이터 출처, 한계를 자세히 정리한다.

장점은 제출 자료와 심사 대응에 강하다는 점이다. 단점은 실제 데모 화면을 보는 순간에는 설득력이 약하게 느껴질 수 있다.

### 접근 C: 리포트 중심 산출 근거

분석 리포트 화면에 “산출 근거 요약” 섹션을 추가하여 주요 수치와 근거를 표 형태로 보여준다.

장점은 결과 보고서 흐름에 잘 맞는다는 점이다. 단점은 대시보드 조작 중에는 근거 확인이 늦게 나타난다.

## 선택한 설계

접근 A와 B를 함께 적용한다. 대시보드에서는 수치 옆에서 바로 근거를 확인하고, 문서에서는 같은 기준을 제출용 방법론으로 정리한다. 리포트에는 가벼운 요약만 추가해 결과 화면에서도 근거가 끊기지 않게 한다.

## 화면 설계

### 데이터 근거 패널 개편

기존 `데이터 근거` 패널을 단순 출처 목록에서 다음 구조로 바꾼다.

- 데이터 상태: TourAPI 실조회, 일부 보완, 샘플 대체 여부
- 기준 시점: 데이터 조회 시간 또는 샘플 기준일
- 사용 데이터: 축제 후보, 주변 관광지, 유사 축제, 트렌드 신호, 사용자 입력값
- 한계 고지: 개인정보 미수집, 실제 방문객 집계가 아닌 사전 예측 모델, 샘플 데이터 사용 여부

### 지표별 근거 보기

주요 지표에는 작은 `근거 보기` 버튼 또는 정보 아이콘을 둔다.

- 흥행 예측 지수
- 최고 밀집 위험도
- 예산 효율성 점수
- 지역 상권 유출 연계도
- 안전관리 요원 추천 배치 인원
- 의료/구급 인력 추천 배치 인원
- 주차 수용 차오름 비율
- 예상 지역 상권 소비 창출액과 ROI

버튼을 누르면 같은 사이드 패널에서 다음 내용을 보여준다.

- 지표 설명
- 사용 데이터
- 산출 방식 요약
- 주요 영향 요인
- 신뢰도
- 해석 시 주의사항

### 리포트 근거 요약

리포트 화면에는 “산출 근거 요약” 섹션을 추가한다. 상세 산식 전체를 반복하지 않고, 각 지표의 출처와 해석 기준을 짧게 보여준다. 제출 데모에서는 리포트만 봐도 결과 수치가 임의값처럼 보이지 않도록 한다.

## 데이터 구조 설계

새로운 근거 데이터 구조를 추가한다.

```ts
interface MetricEvidence {
  metricId: string;
  title: string;
  summary: string;
  dataSources: string[];
  formulaSummary: string;
  assumptions: string[];
  confidence: "high" | "medium" | "low";
  limitations: string[];
  contributors: Array<{
    label: string;
    value: string;
    effect: "positive" | "neutral" | "risk";
  }>;
}
```

이 구조는 화면 컴포넌트와 문서에서 같은 용어를 쓰기 위한 기준이다. 실제 계산 로직은 기존 `forecast.ts`, `simulation.ts`, `impactMetrics.ts`를 유지하고, 근거 생성 로직은 별도 서비스로 분리한다.

## 컴포넌트 설계

### `MetricEvidenceDrawer`

선택된 지표의 근거를 보여주는 공통 사이드 패널이다.

담당 역할:

- 지표명과 요약 표시
- 사용 데이터 목록 표시
- 산식 요약 표시
- 신뢰도 배지 표시
- 한계와 주의사항 표시

### `EvidenceButton`

KPI 카드나 패널 내부에서 근거 패널을 여는 작은 버튼이다. 대시보드의 시각적 밀도를 높이지 않기 위해 텍스트는 짧게 유지한다.

### `metricEvidence.ts`

기존 예측, 시뮬레이션, 경제효과 결과를 받아 지표별 근거 객체를 생성한다.

담당 역할:

- 화면에 표시할 설명 문구 관리
- 지표별 산식 요약 관리
- 실데이터/샘플 데이터 상태에 따른 신뢰도 문구 생성
- 리포트에서 재사용할 근거 요약 제공

## 데이터 흐름

1. 사용자가 지역, 기간, 축제 후보, 예산, 수용 인원을 입력한다.
2. TourAPI와 트렌드 어댑터가 관광 맥락 데이터를 생성한다.
3. 예측 서비스가 예상 방문객, 시간대별 수요, 흥행 지수를 계산한다.
4. 시뮬레이션 서비스가 격자별 혼잡도와 병목 후보를 계산한다.
5. 영향 지표 서비스가 안전 인력, 주차 수용성, ROI를 계산한다.
6. 근거 서비스가 각 지표의 출처, 산식, 신뢰도, 한계를 생성한다.
7. 대시보드와 리포트가 같은 근거 데이터를 사용한다.

## 오류 및 예외 처리

- TourAPI 조회 실패 시 `샘플 데이터 대체 사용` 상태를 명확히 표시한다.
- 일부 데이터만 조회된 경우 `일부 보완` 상태를 표시하고, 어떤 항목이 보완되었는지 설명한다.
- 산식에 필요한 값이 없으면 “사용자 입력값 기준 추정”으로 표시한다.
- 신뢰도는 데이터 수집 상태와 후보 수에 따라 `높음`, `보통`, `낮음`으로 표시한다.

## 문서 설계

`docs/data-methodology.md`를 추가한다.

문서 구성:

- 데이터 출처
- 지표 정의
- 산출 방식
- 샘플 및 보완 데이터 사용 기준
- 개인정보 및 보안 고려
- 심사 대응용 설명 문구

이 문서는 정부 사업 제출 자료에서 “데이터 기반 의사결정”, “공공데이터 활용”, “위험 진단 근거”를 설명하는 근거 문서 역할을 한다.

## 테스트 계획

- 근거 서비스 단위 테스트: 지표별 근거 객체가 올바르게 생성되는지 검증한다.
- 대시보드 렌더링 테스트: `근거 보기` 버튼과 패널 주요 문구가 노출되는지 검증한다.
- 샘플/실데이터 상태 테스트: TourAPI 상태에 따라 신뢰도와 한계 문구가 달라지는지 검증한다.
- 빌드 검증: Vite 빌드가 통과하는지 확인한다.

## 범위에서 제외

- 실제 방문객 통신사 데이터 연동
- 결제 데이터 또는 카드 소비 데이터 연동
- PDF 자동 생성
- 통계 모델 또는 머신러닝 모델 교체
- 개인정보 기반 위치 추적

이번 단계는 기존 휴리스틱 예측 로직을 교체하는 작업이 아니라, 현재 예측값의 근거를 화면과 문서에서 납득 가능하게 만드는 작업이다.

## 승인 기준

- 대시보드 주요 수치마다 출처와 산출 근거를 확인할 수 있다.
- 샘플 데이터와 실데이터 사용 상태가 명확히 구분된다.
- 리포트에서도 산출 근거 요약이 확인된다.
- 제출 문서에서 지표 정의와 산식, 한계를 설명할 수 있다.
- 기존 대시보드 톤앤매너와 반응형 레이아웃이 유지된다.
