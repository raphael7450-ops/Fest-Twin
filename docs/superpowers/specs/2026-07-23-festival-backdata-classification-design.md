# Fest-Twin 축제 백데이터 기반 유형 분류 설계

## 목적

Fest-Twin의 수요 예측과 혼잡 진단은 축제의 성격에 따라 다르게 해석되어야 한다. 공연형, 먹거리형, 야간 경관형, 전통문화형, 거리 퍼레이드형은 피크 시간, 체류 시간, 병목 위치, 교통 부담, 예산 효율 판단 기준이 서로 다르다. 따라서 사용자 입력과 TourAPI 현재 축제 정보만으로 판단하지 않고, data.go.kr의 과거·표준 축제 백데이터를 보조 근거로 붙여 축제 유형을 설명 가능한 방식으로 분류한다.

## 사용할 공공데이터 후보

### 1. 전국문화축제표준데이터

- 출처: 공공데이터포털 `전국문화축제표준데이터`
- URL: https://www.data.go.kr/data/15013104/standard.do
- 확인일: 2026-07-23
- 성격: 지역을 대표하는 문화, 예술, 국가유산, 전통, 생태, 자연, 지역특성 소재의 정기 개최 축제 정보
- 주요 필드: 축제명, 개최장소, 축제시작일자, 축제종료일자, 축제내용, 주최·주관기관, 주소, 위도, 경도
- 활용: 축제명·내용·장소 기반 유형 태그 추출, 개최 기간과 지역 기반 유사 축제 검색

### 2. 한국관광공사 국문 관광정보 서비스 TourAPI

- 출처: 공공데이터포털 `한국관광공사_국문 관광정보 서비스_GW`
- URL: https://www.data.go.kr/data/15101578/openapi.do
- 확인일: 2026-07-23
- 성격: 행사정보, 공통정보, 소개정보, 반복정보, 이미지정보 등 최신 관광정보 OpenAPI
- 활용: 현재 또는 예정 축제 후보 조회, 상세 설명과 위치, 이미지, 행사 기간 보강
- 현재 Fest-Twin 연동 상태: 지역·기간 기반 축제 후보 조회와 주변 관광지 조회에 사용 중

### 3. 문화체육관광부 지역축제 정보

- 출처: 공공데이터포털 `문화체육관광부_지역축제 정보`
- URL: https://www.data.go.kr/data/15143175/fileData.do?recommendDataYn=Y
- 확인일: 2026-07-23
- 성격: 광역·기초자치단체별 지역축제 현황 데이터
- 주요 필드 후보: 축제명, 유형, 장소, 개최기간, 주기, 방식, 최초 개최연도, 예산, 방문객 수, 담당기관
- 활용: 유형 분류의 핵심 백데이터, 유사 축제의 예산·방문객·운영 방식 비교

## 분류 방식

1차 구현은 설명 가능한 규칙 기반 분류로 시작한다. 모델이나 비공개 AI 추론을 전면에 세우지 않고, 데이터 필드와 키워드 매칭 결과를 근거 drawer에서 확인할 수 있게 한다.

### 대표 유형

- `공연/콘서트형`: 무대, 공연, 콘서트, 버스킹, 음악, K-pop
- `먹거리/시장형`: 푸드, 음식, 먹거리, 장터, 야시장, 특산물, 판매부스
- `전통/문화형`: 전통, 문화재, 국가유산, 민속, 역사, 제례, 한복
- `야간/미디어아트형`: 빛, 야간, 미디어, 라이트, 조명, 불빛, 경관
- `체험/참여형`: 체험, 워크숍, 만들기, 교육, 가족, 어린이
- `거리/퍼레이드형`: 퍼레이드, 행진, 거리, 도로, 카니발, parade
- `자연/생태형`: 꽃, 벚꽃, 국화, 생태, 자연, 숲, 강, 바다
- `불꽃/카운트다운형`: 불꽃, 카운트다운, 해맞이, 새해, 폐막, 피날레

### 보조 태그

대표 유형 하나만 사용하지 않고 보조 태그를 함께 붙인다. 예를 들어 `강남 미디어 윈터페스타`는 `야간/미디어아트형`을 대표 유형으로 두고, `공연/콘서트형`, `도심 접근형`, `포토존 집중형`을 보조 태그로 둘 수 있다.

### 유사 축제 매칭

유사도는 다음 요소를 합산한다.

- 제목·설명 키워드 유사도
- 지역 또는 권역 일치
- 개최 계절과 기간 유사도
- 장소 성격: 실내, 야외광장, 거리, 공원, 해변, 시장
- 축제 유형 일치
- 예산 규모와 예상 방문객 규모의 근접성

유사 축제는 기본 5~12건 범위로 표시한다. 데이터가 부족하면 `유사 축제 부족` 상태로 표시하고, 키워드 기반 분류와 사용자 입력을 더 크게 반영한다.

## 예측 반영 방식

축제 유형은 기존 지표를 대체하지 않고 가중치로 보정한다.

| 유형 | 수요 보정 | 혼잡 보정 | 예산·ROI 보정 | 교통 보정 |
| --- | --- | --- | --- | --- |
| 공연/콘서트형 | 공연 시작·종료 전후 피크 증가 | 무대·출입구 병목 증가 | 안전·무대 운영비 중요 | 종료 시간 교통 집중 |
| 먹거리/시장형 | 체류 시간 증가 | 부스·화장실 주변 밀집 증가 | 1인당 소비 단가 증가 | 주차 회전율 저하 |
| 야간/미디어아트형 | 18~22시 피크 증가 | 포토존·동선 교차점 증가 | 야간 안전·조명 비용 중요 | 야간 대중교통·주차 부담 |
| 거리/퍼레이드형 | 특정 구간 시간대 집중 | 선형 동선 병목 증가 | 교통통제 비용 중요 | View-T 접근 교통 가중 |
| 자연/생태형 | 주말·낮 시간 증가 | 포토스팟 분산 혼잡 | 지역상권 연계 중요 | 자가용 접근 비중 증가 |
| 불꽃/카운트다운형 | 짧은 시간 초피크 | 퇴장·관람 구역 위험 증가 | 안전 인력·통제 비용 중요 | 종료 직후 교통 급증 |

## 화면 설계

대시보드에는 `축제 유형 진단` 패널을 추가한다.

- 대표 유형: 예) `야간/미디어아트형`
- 보조 태그: 예) `공연형`, `도심 접근형`, `포토존 집중형`
- 유사 축제 근거: 예) `유사 축제 8건`, `평균 방문객 74,000명`, `평균 예산 6.2억 원`
- 적용 보정: 예) `저녁 피크 +12%`, `포토존 병목 +15%`, `접근 교통 +8%`
- 근거 보기 버튼: 백데이터 출처, 조회 조건, 사용 레코드, 누락 필드, 보정값을 표시

좌측 입력 패널에는 사용자가 직접 대표 유형을 수정할 수 있는 선택 항목을 둔다. 자동 분류 결과와 사용자가 수정한 유형이 다르면, 대시보드에 `사용자 조정 반영` 상태를 표시한다.

## 데이터 흐름

1. 사용자가 지역과 기간을 입력한다.
2. TourAPI로 현재 축제 후보를 조회한다.
3. 선택된 축제명, 주소, 기간, 설명을 기준으로 백데이터 후보를 조회한다.
4. 전국문화축제표준데이터와 문화체육관광부 지역축제 정보에서 유사 축제를 찾는다.
5. 키워드, 유형, 지역, 기간, 규모를 점수화한다.
6. 대표 유형과 보조 태그를 산출한다.
7. 수요 예측, 혼잡 시뮬레이션, 안전·물류, 예산 ROI 계산에 유형별 가중치를 적용한다.
8. 모든 사용 데이터와 보정 이유를 근거 drawer에 표시한다.

## 서버 연동 설계

클라이언트에서 data.go.kr 인증키를 직접 사용하지 않는다. 기존 TourAPI 프록시와 같은 방식으로 서버 API를 둔다.

예상 엔드포인트:

```text
GET /api/festival-backdata/similar?name=<축제명>&region=<지역>&startDate=<YYYY-MM-DD>&endDate=<YYYY-MM-DD>
```

응답은 원본 전체가 아니라 화면과 계산에 필요한 정규화 필드만 포함한다.

```ts
interface FestivalBackdataContext {
  classification: {
    primaryType: FestivalType;
    secondaryTags: string[];
    confidence: "high" | "medium" | "low";
  };
  similarFestivals: Array<{
    id: string;
    name: string;
    region: string;
    type?: string;
    startDate?: string;
    endDate?: string;
    budgetMillionKrw?: number;
    visitors?: number;
    similarityScore: number;
  }>;
  adjustments: Array<{
    metricId: string;
    label: string;
    value: number;
    reason: string;
  }>;
  sourceDetails: MetricEvidenceSourceDetail[];
}
```

## 오류 처리와 fallback

- data.go.kr API 실패: 기존 TourAPI·사용자 입력·키워드 규칙으로 분류하고 `백데이터 조회 실패` 표시
- 유사 축제 부족: 대표 유형은 산출하되 confidence를 `low`로 낮춤
- 예산·방문객 필드 누락: 수요 보정에는 제외하고 유형·기간·장소 근거만 사용
- 인증키·원본 URL·민감 헤더: 화면과 문서에 표시하지 않음
- 과거 방문객 수는 실제 예측값이 아니라 `유사 사례 참고값`으로 표시

## 테스트 기준

- 백데이터 프록시는 허용된 query만 통과시키고 인증키를 노출하지 않는다.
- 표준데이터·지역축제 정보의 서로 다른 필드명을 하나의 정규화 모델로 변환한다.
- 축제명과 설명 키워드로 대표 유형과 보조 태그를 산출한다.
- 백데이터가 없을 때도 대시보드가 비어 보이지 않고 fallback 근거를 표시한다.
- 유형별 가중치가 수요 예측, 혼잡, 주차, ROI 지표에 반영되고 근거 drawer에 표시된다.

## 구현 범위

1차 구현은 `설명 가능한 규칙 기반 + 백데이터 유사 사례 조회`까지로 제한한다. 지도 좌표 기반 고급 클러스터링, 머신러닝 모델 학습, 자동 예산 최적화는 후속 과제로 둔다.

## 제출용 설명 문구

Fest-Twin은 data.go.kr의 표준·지역축제 백데이터와 TourAPI의 현재 축제 정보를 결합하여 입력 축제의 대표 유형과 유사 축제를 산출한다. 이 결과는 수요 예측, 군중 시뮬레이션, 안전·물류, 예산 효율성 지표의 보정 근거로 사용되며, 화면의 근거 패널에서 사용 데이터와 보정 사유를 확인할 수 있다. 과거 방문객·예산 정보는 실제 확정값이 아니라 유사 사례 기반의 사전 검토 참고값으로 표시한다.
