# Backdata-Based Plan Prefill Design

## Goal

TourAPI 축제 후보를 선택할 때 사용자가 보는 기획안 입력값 중 `총 예산`과 `예상 수용 인원`을 전년도 또는 유사 지역축제 백데이터 기준으로 자동 추천한다. TourAPI가 예산과 방문객 실적을 직접 제공하지 않기 때문에, 이 기능은 실측 확정값이 아니라 문화체육관광부 지역축제 정보 기반 초기 추천값으로 표현한다.

## Data Rule

- 입력 기준: 선택한 TourAPI 후보의 축제명, 지역, 기간, 기존 키워드
- 매칭 데이터: `getDemandBackdataContext(plan)`의 유사 축제 기준선
- 예산 추천: 최상위 유사 축제의 `budgetMillionKrw`
- 수용 인원 추천: 최상위 유사 축제의 `visitors` 중 20%를 피크 동시 수용 추정값으로 변환
- 하한/상한: 피크 동시 수용 추정값은 최소 1,000명, 최대 방문객 수 이하로 제한

## UX Rule

후보 선택 직후 기획안 입력값을 자동 갱신한다. 단, 사용자가 현재 샘플 기본값이 아닌 예산 또는 수용 인원을 이미 직접 조정한 경우에는 해당 값을 덮어쓰지 않는다.

## Evidence

자동 세팅된 값은 데이터 근거 패널과 KPI 근거에서 기존 지역 수요 백데이터 항목으로 설명된다. 화면 입력칸에는 추천값이 들어가지만, 제출 문서에서는 “유사 축제 실적 기반 초기 추천값이며 담당자가 수정 가능”하다고 설명한다.

## Tests

- 후보 선택 적용 함수가 유사 축제 예산과 방문객 수로 추천값을 반영한다.
- 사용자가 예산 또는 수용 인원을 직접 바꾼 경우 기존 값을 보존한다.
- 앱에서 후보 선택 시 추천값이 입력칸에 표시된다.
