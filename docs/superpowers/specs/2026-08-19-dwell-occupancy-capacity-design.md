# 체류시간 기반 동시점유·시설수용 모델 설계

## 목적

Fest-Twin의 기존 `visitorsByHour`는 일일 예상 방문객을 시간대 가중치로 나눈 값이지만, 밀집도·주차·화장실 계산에서는 동시 체류인원처럼 사용된다. 이 구조는 불꽃놀이, 대형 공연처럼 방문객이 핵심 프로그램까지 장시간 남는 축제의 현장 점유를 과소 추정할 수 있다.

이번 변경은 일일 고유 방문객, 시간대 신규 유입, 동시 체류인원, 이탈인원을 분리하고 각 운영 지표가 올바른 모수를 사용하도록 한다.

## 범위

### 포함

- 시간대 신규 유입량과 체류 잔존율을 결합한 동시 체류인원 계산
- 축제 유형별 기본 체류 프로필과 사용자 평균 체류시간 조정
- 체류시간 근거와 신뢰도 표시
- 동시 체류인원 기반 밀집도·안전인력·대피·주차·화장실 계산
- 고유 방문객 기반 폐기물·경제효과 유지
- 시간대 이탈인원과 종료 직후 이탈 집중도 표시
- 주차면 수와 화장실 변기 수의 명시적 기획 입력
- 기존 저장 시나리오와 기존 `ForecastResult` 소비 코드의 호환
- 화면, 근거 보기, CSV, 인쇄/PDF의 동일한 산정 근거

### 제외

- 한국관광 데이터랩 화면 비공식 스크래핑
- 통신사 유료 API 계약 및 실시간 기지국 데이터 연동
- 성별 화장실 이용률 세분화
- 대중교통 차량별 배차 최적화
- 출입 게이트 센서의 실시간 운영 관제

## 데이터 우선순위

체류 프로필은 다음 순서로 선택한다.

1. 동일 축제의 과거 통신·게이트 관측값
2. 동일 장소·동일 계절의 관광지 체류 벤치마크
3. 유사 축제의 관측값
4. 축제 유형별 기본 프로필
5. 기획자 조정값

현재 저장소에는 검증된 축제별 체류시간 관측값이 없으므로, 첫 배포에서는 유형별 기본 프로필을 사용하고 `낮음` 신뢰도로 표시한다. 검증되지 않은 실측값은 만들지 않는다. 향후 공식 보고서 값은 독립된 벤치마크 데이터 파일을 통해 추가한다.

사용자 조정은 자동 프로필을 삭제하지 않고 평균 체류시간만 덮어쓴다. 근거에는 자동 선택 프로필, 조정 전후 값, 조정 주체를 함께 남긴다.

## 체류 프로필

프로필 유형은 기존 축제명, 키워드, 유사 축제 유형, 프로그램 시간표를 사용해 설명 가능한 규칙으로 선택한다.

| 유형 | 기본 평균 체류 | 특성 |
| --- | ---: | --- |
| 불꽃·카운트다운·대형 공연 | 270분 | 핵심 공연 전 높은 잔존율, 종료 직후 대량 이탈 |
| 먹거리·체험형 | 180분 | 점심·저녁 유입 교체, 중간 회전 |
| 야간 경관·미디어형 | 150분 | 저녁 유입 집중, 비교적 완만한 회전 |
| 거리·퍼레이드형 | 120분 | 구간 이동과 짧은 관람, 높은 회전 |
| 주간 종합형 | 150분 | 체험과 공연 혼합, 중간 잔존율 |

허용 평균 체류시간은 30~720분이다. 사용자 입력이 범위를 벗어나거나 유효하지 않으면 자동 프로필을 유지한다.

기본 경과시간별 잔존율은 다음 배열을 사용한다. 배열의 첫 값은 입장 시간, 다음 값부터 1시간 경과 단위다.

| 유형 | 기본 잔존율 |
| --- | --- |
| 불꽃·카운트다운·대형 공연 | `[1, 0.98, 0.94, 0.86, 0.68, 0.38, 0.12, 0]` |
| 먹거리·체험형 | `[1, 0.88, 0.68, 0.42, 0.18, 0]` |
| 야간 경관·미디어형 | `[1, 0.82, 0.55, 0.28, 0.08, 0]` |
| 거리·퍼레이드형 | `[1, 0.65, 0.28, 0.05, 0]` |
| 주간 종합형 | `[1, 0.82, 0.55, 0.25, 0.07, 0]` |

사용자 평균 체류시간이 기본값과 다르면 `사용자 평균 / 기본 평균` 비율로 경과시간 축을 늘리거나 줄이고 선형 보간한다. 결과는 다시 0~1 범위와 단조 감소 조건으로 정규화한다.

## 계산 모델

### 1. 신규 유입

기존 시간대 가중치 분배 결과는 의미를 명확히 바꿔 `arrivalsByHour`로 저장한다.

```text
시간대 신규 유입 = 일일 고유 방문객 × 시간대 유입 가중치 / 전체 가중치 합
```

시간대 신규 유입의 합은 반올림 오차를 보정해 일일 고유 방문객과 같아야 한다.

### 2. 동시 체류

각 시간대 신규 유입을 하나의 코호트로 보고, 경과시간별 잔존율을 적용한다.

```text
동시 체류인원(t) = Σ 신규 유입(t-k) × 잔존율(k)
시간대 이탈인원(t) = 이전 동시 체류 + 신규 유입 - 현재 동시 체류
누적 입장객(t) = Σ 신규 유입(시작~t)
```

잔존율은 평균 체류시간과 프로필 유형으로부터 생성되는 단조 감소 배열이다. 잔존율은 0~1 범위이고 시간이 지날수록 증가할 수 없다. 불꽃·대형 공연형은 핵심 프로그램 종료 시각 전까지 기본 프로필보다 잔존율을 높이고, 종료 다음 시간대에 이탈을 집중시킨다.

불꽃·대형 공연형의 핵심 종료시각은 `expectedDraw`가 가장 큰 프로그램의 `endHour`로 정한다. 해당 프로그램 종료 전에 입장한 코호트에는 종료시각까지 최소 잔존율 0.85를 적용한다. 종료 1시간 뒤 잔존율은 최대 0.18, 2시간 뒤에는 0으로 제한한다. 동일 `expectedDraw`이면 더 늦게 끝나는 프로그램을 선택한다. 프로그램이 없으면 일반 잔존율만 사용한다.

### 3. 기존 필드 호환

- `ForecastResult.arrivalsByHour`: 신규 유입
- `ForecastResult.occupancyByHour`: 동시 체류
- `ForecastResult.departuresByHour`: 이탈
- `ForecastResult.cumulativeArrivalsByHour`: 누적 입장
- `ForecastResult.visitorsByHour`: 동시 체류의 호환 별칭
- `ForecastResult.expectedVisitors`: 일일 고유 방문객
- `ForecastResult.peakHour`: 최대 동시 체류 시각

기존 수동 테스트 픽스처처럼 새 필드가 없는 `ForecastResult`는 `visitorsByHour`를 동시 체류로 해석한다.

평일·주말 프로필에도 같은 네 가지 시간대 배열과 체류 프로필을 포함한다.

## 지표별 모수

| 지표 | 사용 값 |
| --- | --- |
| 물리 밀집도 | 최대 동시 체류인원 |
| 격자 혼잡 시뮬레이션 | 선택 시간의 동시 체류인원 |
| 안전·의료 인력 | 최대 동시 체류인원과 병목 수 |
| 대피시간 | 최대 동시 체류인원 |
| 주차 점유 | 시간대 동시 체류인원 × 승용차 분담률 ÷ 차량당 인원 |
| 주차 만차 시점 | 점유 차량이 입력 주차면을 처음 초과하는 시간 |
| 화장실 필요 수 | 최대 동시 체류인원 ÷ 변기 1기당 수용인원 |
| 화장실 대기 | 필요 수와 입력 변기 수의 차이 |
| 종료 교통 압력 | 최대 시간대 이탈인원 |
| 폐기물·경제효과 | 일일 고유 방문객 |

승용차 분담률 18%, 차량당 2.5명, 변기 1기당 피크 동시 체류 250명은 기존 가정을 유지하되 근거에 명시한다.

주차면 수 또는 화장실 수가 입력되지 않은 경우 결과를 임의의 준비 수량으로 확정하지 않는다. 규모 기반 권장값과 `기획 입력 필요` 상태를 구분해 표시한다.

## 도메인 모델

`FestivalPlan`에 다음 선택 필드를 추가한다.

```ts
interface FestivalPlan {
  averageDwellMinutes?: number;
  parkingCapacityVehicles?: number;
  restroomFixtureCount?: number;
}
```

체류 계산 결과는 다음 구조를 사용한다.

```ts
type DwellProfileKind =
  | "fireworks-performance"
  | "food-experience"
  | "night-exhibition"
  | "street-parade"
  | "daytime-general";

interface DwellProfile {
  kind: DwellProfileKind;
  label: string;
  averageMinutes: number;
  sourceType: "festival-observed" | "place-benchmark" | "similar-festival" | "type-default" | "user-adjusted";
  sourceName: string;
  confidence: "high" | "medium" | "low";
  retentionRates: number[];
}

interface VisitorFlowPoint {
  hour: number;
  visitors: number;
}
```

기존 시나리오 정규화는 새 숫자 필드를 유한한 양수일 때만 보존한다. 필드가 없는 과거 시나리오는 자동 체류 프로필과 미입력 시설 상태로 정상 복원한다.

TourAPI 축제 후보를 새로 선택하면 기존 축제에서 사용자가 입력한 `averageDwellMinutes`, `parkingCapacityVehicles`, `restroomFixtureCount`는 자동으로 새 축제로 승계하지 않는다. 축제 변경 트랜잭션에서 세 값을 비우고 새 축제 유형 프로필을 다시 선택한다. 저장 시나리오를 복원할 때만 저장된 값을 그대로 복원한다.

## 서비스 경계

### `visitorOccupancy.ts`

- 축제 유형과 체류 프로필 선택
- 평균 체류시간 조정
- 잔존율 생성 및 검증
- 유입 배열에서 동시 체류·이탈·누적 입장 계산
- 일일 방문객 합계 보정

이 서비스는 순수 함수로 구성하며 UI, 네트워크, 저장소에 의존하지 않는다.

### `forecast.ts`

- 일일 고유 방문객과 신규 유입 가중치까지만 결정
- `visitorOccupancy.ts`를 호출해 시간대 흐름 생성
- 평일·주말에도 동일 계산 적용

### 안전·시설 서비스

- `simulation.ts`, `safetyDecisionMetrics.ts`, `impactMetrics.ts`는 동시 체류 배열 사용
- `capacityAndSafetyForecast.ts`는 동시 체류, 이탈, 명시적 시설 수량 사용
- 새 필드가 없는 테스트·레거시 결과는 호환 별칭 사용

## 화면 설계

### 기획 입력

`PlanForm`에 `체류·시설 가정` 구역을 추가한다.

- 자동 체류 프로필명과 신뢰도
- 평균 체류시간 숫자 입력(분)
- 주차 가능 차량 숫자 입력
- 화장실 변기 수 숫자 입력
- 자동값 복원 명령

입력 컨트롤은 기존 B2G 운영툴 스타일을 따르고 그라데이션을 사용하지 않는다. 자동 프로필 설명은 짧게 표시하고 긴 방법론 설명은 근거 보기로 보낸다.

### 수요 예측

기존 시간대 막대 차트에 `동시 체류`와 `신규 유입` 모드를 제공한다. 기본 모드는 시설·안전 판단에 직접 쓰이는 `동시 체류`다.

요약에는 다음을 표시한다.

- 일일 고유 방문객
- 최대 동시 체류인원과 시각
- 평균 체류시간
- 최대 시간대 이탈인원과 시각

### 시설 수용

- 주차: 최대 점유 차량, 입력 주차면, 최초 만차 예상시각
- 화장실: 필요 수, 입력 수, 부족 수, 예상 대기
- 종료 교통: 최대 이탈 인원과 시간
- 입력값이 없으면 확정 점유율 대신 권장 수량과 입력 필요 상태 표시

`InfrastructureCapacityForecast`는 주차와 화장실 각각 `"available" | "input-required"` 상태를 가진다. `input-required`에서는 권장 수량은 제공하되 점유율, 부족 수, 만차 시각을 확정값으로 표시하지 않는다.

## 근거와 보고서

근거 보기, CSV, 인쇄/PDF에 다음을 동일하게 기록한다.

- 체류 프로필 유형
- 평균 체류시간
- 데이터 출처 유형과 신뢰도
- 자동값인지 사용자 조정인지
- 일일 고유 방문객, 최대 신규 유입, 최대 동시 체류, 최대 이탈
- 주차·화장실 입력값 또는 미입력 상태
- 주요 계산식과 가정

`시간대 방문객`처럼 의미가 모호한 표현은 `시간대 신규 유입` 또는 `동시 체류인원`으로 교체한다.

## 오류 처리와 안전장치

- 모든 인원과 시설 값은 유한한 0 이상의 정수로 정규화한다.
- 평균 체류시간은 30~720분으로 제한한다.
- 잔존율은 0~1, 단조 감소로 검증한다.
- 동시 체류와 누적 입장은 음수가 될 수 없다.
- 누적 입장은 일일 고유 방문객을 초과할 수 없다.
- 이탈인원 합은 운영 종료 후 최종 잔류인원을 포함해 총 유입과 일치해야 한다.
- 프로필 판별 실패 시 주간 종합형 기본값을 사용하고 낮은 신뢰도를 표시한다.
- 외부 관측 데이터가 없다는 사실을 숨기지 않는다.

## 테스트 전략

### 단위 테스트

- 유입 합계가 일일 고유 방문객과 일치
- 장기 체류 프로필이 단기 프로필보다 피크 동시 체류를 높임
- 불꽃형은 핵심 프로그램 전 누적되고 종료 후 이탈이 집중됨
- 동시 체류·이탈·누적 입장 보존 법칙
